# D92 E0全量消融实验数据汇总与详细分析

> 统计截止日期：2026-08-19
> 核心协议：`p2_min_v1`
> 当前证据终态：`SCREENING_COMPLETE_NOT_FRESH_CONFIRMED_NOT_PROMOTABLE`

## 1.结论摘要

截至2026-08-19，D92 E0已经形成三层消融证据：上游Phase1冻结bundle消融、Phase2注册前状态对照、Stage2-C D92 E0支持状态模块消融。新增的FFT96-only/RF32-only正式筛选补齐了联合特征内部结构。本文只汇总已完成实验，不启动新run，不把pilot、技术停止或历史诊断混入正式性能结果。

数据支持六项明确结论：

1.联合辅助特征是D92 E0最主要的Stage2-C性能来源。完整D92 E0相对只保留identity160的`P2-A0`，H提高0.3081，分层bootstrap 95%CI为[0.2803,0.3261]；旧类、新类和两类floor同时改善。
2.联合特征的有效信息主要由FFT96承担。在新增正式run中，identity160+FFT96相对identity160+RF32的H提高0.265428，旧类/新类准确率分别提高0.235556/0.277212，五个receiver、五个K/新类切片和三个场景方向一致。
3.现有证据不能证明RF32在完整288维模型中无用。A1/A2是同run严格配对，但A1与历史P2-FULL不是同run配对；“删除RF32”仍缺少完整288维与identity160+FFT96的同row正式对照。
4.地面扰动谱与Cauchy稳健中心模块B在当前screening中没有可分辨的平均收益。`FULL−B0`的H差约为0，主指标置信区间跨0。该结论只适用于当前固定地面扰动谱、LEO弱信道模拟、receiver/K/场景和单一class draw。
5.任务均衡协方差C和Fisher安全残差E提供小幅旧类保护，但都伴随轻微新类代价。双几何D0/D1/D2同时改变几何、Fisher和rollback路径，只能作为复合功能组对照。
6.量化模块F已经证明状态存储压缩，尚未证明计算加速。F3相对FP32 head减少约49%存储并保持99.9803%预测一致率，但当前路径解码为FP32点积，没有整数kernel和端到端目标硬件时延。

## 2.范围与命名边界

### 2.1本文纳入的实验

- Phase1 T1：冻结bundle的P1-FULL、P1-SUP及A/B/C/D模块消融。
- Phase1标签率：ρ=0.005、0.01、0.02、0.05、0.10敏感性。
- Phase2 States：`DA1_REG0`注册前旧类状态的Stage2-A/Stage2-B对照。
- Stage2-C原始主矩阵：7个同权限基线、完整`P2-FULL`和A–F模块消融。
- Stage2-C特征补充矩阵：`P2-A1=identity160+FFT96`和`P2-A2=identity160+RF32`。

### 2.2本文不纳入主消融排名的实验

- D92-Lite、D138及其他候选诊断：方法身份和目标不同。
- singleton session与batch registration：属于注册生命周期对照，不是模块消融。
- MRIOR-SDA、DADDA-SDA等论文复现：属于不同权限/任务的外部方法比较。
- `d92_e0_fft96_rf32_ablation_pilot_20260819_v2`：只验证执行路径；v1模块路径故障没有性能结果。

### 2.3容易混淆的名称

“D92 E0”是完整方法名称；`P2-E0`则是关闭Fisher residual的消融臂。两者不是同一个概念。`P2-FULL`是完整D92 E0参考臂，`P2-F3`是其双层残差INT8逻辑臂，并在原始screen中复用`P2-FULL`的物理预测。

## 4.协议、样本与指标

Phase2遵守`p2_min_v1`：每个clean/raw物理IQ在Phase2前只产生一个固定`leo_*_weak`接收观测；FFT、均衡和数学视图只能读取该固定received-IQ，不增加K。K-shot中的K个样本必须对应K个独立物理样本。support与query物理ID不相交；query只用于测试，不能更新中心、协方差、阈值、量化状态或类别排序。truth在prediction closure后由独立scorer连接。

Stage2-C每个实验臂包含：

- 5个target receiver：`20-1`、`3-19`、`7-14`、`7-7`、`8-8`；
- 5个K/新类切片：K1/new20、K2/new20、K5/new20、K10/new20、K10/new5；
- 3个development seed；
- 3个LEO弱信道场景：clear、low-elevation、rain；
- 75个identity row和225个scenario unit；
- 每个scenario unit包含120个旧类query和400个新类query。

## 16.证据能支持什么

可以支持：

- D92 E0的Stage2-C主性能主要来自联合辅助特征，FFT96是其中的主导分支。
- B在当前screening中没有可分辨平均收益；C/E是小幅旧类保护模块；D组当前证据因果不纯。
- 完整D92 E0只比最强同权限LDA基线高0.46–0.68个百分点H，优势小但在原始同rowscreen中方向稳定。
- F3完成状态存储压缩，并维持接近不变的预测。
- K、receiver、场景和类别尾部均显著影响结果；总体均值不能替代分层报告。

不能支持：

- 不能把3个development seed、1个class draw的Stage2-C结果称为fresh confirmation。
- 不能把A1接近历史FULL写成“RF32已被证明无用”；两者不是同run严格配对。
- 不能把RF32-only表现差写成RF32在完整模型中有害。
- 不能把D0略高于FULL写成Fisher有害或full-only最优。
- 不能声称INT8推理加速、端到端实时、目标星载硬件达标或真实在轨验证。
- 不能把地面已知扰动谱覆盖到未知卫星信道/未知接收机；当前LEO证据是模拟压力测试。

## 17.优先级建议

若目标是简化D92 E0并保持性能，现有证据给出的顺序是：

1.保留FFT96。A1相对A2的同row优势大且跨receiver/K/场景一致。
2.用同一run补齐P2-FULL与P2-A1，决定RF32能否正式删除；在该证据返回前，只能把RF32标记为“边际贡献未识别”。
3.优先验证删除B。当前FULL−B0主指标接近零，但真实未知卫星域仍需要独立压力证据。
4.C和E按旧类floor需求取舍。两者平均H收益小，主要价值是旧类保护。
5.D必须重新做严格单因素拆解，不能直接依据D0/D1/D2裁剪。
6.部署状态优先F3而不是F2：F3精度保持更稳；是否加速取决于目标硬件整数kernel。
