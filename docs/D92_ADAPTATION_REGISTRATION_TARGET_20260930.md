# D92旧类适应与新类注册的渐进优化目标

日期：2026-09-30。依据用户本轮明确说明，本任务继续在BranchLocalRidge及当前优化候选上逐步改进。下列数值是理想目标，不是每个候选必须一次达到的硬性淘汰条件，也不授权中断、修改或重启健康实验。

## 用户希望达到的效果

1. 只使用目标域旧类support完成适应后，旧类准确率明显上升，理想提升至少10个百分点。
2. 加入目标域新类support完成注册后，尽量保住已获得的旧类适应收益，理想旧类准确率下降不超过1个百分点。
3. 新类准确率本身较高，并接近注册后的旧类准确率，理想绝对差距不超过3个百分点。

三项共同描述最终方向。实际研发允许逐步接近；每次如实报告收益、退化和距理想目标的差距。H保留为辅助综合指标，不能代替上述三个效果。新旧准确率都低但彼此接近，不能被解释为达到“新类准确率很高”的愿望；报告必须同时给出两个绝对准确率，不另造未经用户指定的绝对准确率门槛。

## 三阶段的准确口径

| 阶段 | 合法信息与状态 | 主要记录 |
|---|---|---|
| A：适应前 | 合规冻结的地面模型/旧类决策规则，不使用本row的target support拟合 | 同一旧类query上的A_old |
| B：旧类适应后 | 仅当前合法旧类support；旧类注册表 | 同一旧类query上的B_old |
| C：新类注册后 | 保持同一旧类support，加入合法新类support；面对全部旧类与新类统一竞争 | C_old、C_new、H |

适应收益为 `B_old - A_old`；注册后的旧类下降为 `B_old - C_old`，负值表示旧类进一步改善；新旧类差距为 `abs(C_new - C_old)`。计算用未四舍五入的比例，展示转换为百分点。

A/B/C必须对同一物理旧类query配对，保持receiver、scene、model seed、support seed、K、旧类support身份和固定received观测一致。不能拿不匹配的新增0类任务均值与其他任务均值相减来声称遗忘。所有拟合、注册状态及逐样本预测先固定；独立scorer之后连接truth，识别旧/新分组并计算指标。C阶段预测器始终面对全部已注册类，不能利用query的真实旧/新身份缩小候选集合。

按既有完整矩阵报告K=1/5/10/20、旧类6个、新增类0/2/5/10/20；K表示每类物理support数量，联合support总量为 `(6 + 新增类数量) * K`。新增0类行用于旧类适应诊断，C_new与新旧差距记N/A。保持逐K及K×新增类数量表；分层结果用于呈现真实范围，不自动追加“所有单元同时过理想阈值”的门槛。

## 当前实现能证明什么

当前冻结的LocalRidge与LocalMargin都对每个split的全部合法support重新拟合一个头，没有接收先前旧类适应状态的接口。LocalRidge会重新估计核几何并求解，LocalMargin的优化变量从零初始化；`old_classes`用于输入校验和指标分组，不提供旧类状态保留约束。

依据：[LocalRidge拟合接口](../code/cvsrffi/d92_branch_local_ridge.py)、[LocalMargin拟合接口](../code/cvsrffi/d92_branch_local_margin.py)、[LocalRidge预测入口](../tools/evaluate_d92_branch_local_ridge.py)、[LocalMargin预测入口](../tools/evaluate_d92_branch_local_margin.py)。独立query-blind源码核查由branch_local_core完成，未读取当前或历史query分数。

这类联合重新拟合可以评价旧类适应及加入新类后的行为变化，本身不构成协议违规；但不能据此宣称已经实现“继承旧类适应状态的顺序抗遗忘”。旧类下降也可能包括新增类别引入的竞争，不等价于纯粹的参数遗忘。必须区分行为指标与实现机制。

当前scorer中的 `forgetting` 是新增0类独立拟合与联合注册独立拟合的旧类准确率差值。使用它之前必须核实物理配对，报告中明确这是独立重新拟合的前后对照。不得把旧类状态未改变或旧类内部排序保持，直接当作全注册类竞争下的准确率不会下降。

既有 `frozen_dg` 对应A，使用冻结Phase1原生logits，不拟合target support；本方法的 `new_count=0` 对应B，不能拿原D92的B替代另一方法自己的B。D92记录中的 `same_D92_old_only_before_exact_d81` 以及scorer的 `before` 指B，不是A。A每模型/RX/scene只记录一次，其附带的首个旧类split的K/support_seed不构成适应条件；分析时按真实来源和旧类query物理ID绑定，不能仅据这些偶然字段配对一个K。B−A包含冻结DG到适应系统的分类头替换收益，不单独等同于同一分类头的参数更新收益。

独立query-blind源码检查已确认builder按不含新增类数量的种子生成旧类support，旧类query也来自固定池；新增类数量只改变注册表及最终query打乱顺序。因此旧类身份集合在设计上可配对，但不能按行位置直接相减。实际分析仍核对物理ID，源码保证不冒充实际产物验证。依据：[builder](../tools/build_d92_confirmation_data.py)、[原D92与DG输出](../tools/cvs_d92_matched.py)、[独立scorer](../tools/score_d92_confirmation.py)。该检查由local_margin_entry完成，未读取实际query值。
