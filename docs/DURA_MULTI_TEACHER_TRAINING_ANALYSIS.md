# DURA 多教师与训练重复计算分析

日期：2026-10-22。本次只分析现有代码、训练成本 CSV、阶段完成元数据及原采样器，不读取 IQ、checkpoint 或 truth，不启动新训练、不修改健康队列。状态：`METADATA_AND_INDEX_ANALYSIS_ONLY`，尚无新实现的实测加速或识别保持结果。

## 1. 当前“多个教师”实际是什么

DURA 的完整谱系是八段训练，其中五段包含独立的冻结教师蒸馏。教师依赖如下，不是一个学生每步同时调用五个教师：

| 训练段 | 冻结教师或前缀 | 需要缓存的内容 |
|---|---|---|
| coarse | 直接用配对 clean IQ，无网络教师 | 固定 clean 谱目标等 |
| action | 上段 coarse 固定；另用已缓存的物理作用监督 | coarse 输出；已有作用监督保持 |
| R17 | 上段 action/coarse 固定，不做外部 IQ 教师蒸馏 | 固定上下文；prior 仍在线训练 |
| R38 | R17 | 三阶段教师恢复 IQ |
| R44 | R38 | 三阶段教师恢复 IQ |
| R46 | R44 | 三阶段教师恢复 IQ |
| R65 | R46 | 三阶段教师恢复 IQ |
| R69 | R65 | 教师第 2、第 3 阶段恢复 IQ |

代码依据：`experiments/cric_dura_comparison/g_train.py`、`g_lineage.py`、`g_student.py`、`g_ablation.py`、`continuation_setup.py`。训练中的 R38 及后续学生会联合更新粗恢复、作用估计器和 prior，不能因属性名叫 `frozen` 就缓存这些学生组件的输出。教师本身与实际冻结的前缀才适合复用。

已实现的复用不重复计算为新收益：同契约 G 已跨 F 模型 seed 共用；21 条消融已共用原 R65 checkpoint；源 IQ 观察生成已有物理 ID 去重。尚待优化的是冻结教师的预测计算，而非把本来就共用的 checkpoint 再登记一次。

## 2. 真正耗时的段在上游

本地阶段快照时间为 2026-10-22 10:23:28 UTC，即香港时间 18:23:28；包含 21 条已完成完整谱系，每段各 21 个完成时间。它是历史快照，不是本次远端实时状态。

| 阶段 | 每条该段耗时中位数 | 占全部阶段累计 elapsed 的比例 |
|---|---:|---:|
| coarse | 16.26 min | 4.90% |
| action | 12.08 min | 3.84% |
| R17 | 29.04 min | 9.32% |
| R38 | 71.23 min | 23.27% |
| R44 | 67.92 min | 22.19% |
| R46 | 68.78 min | 22.32% |
| R65 | 23.48 min | 7.80% |
| R69 | 19.59 min | 6.35% |

R38/R44/R46 合计 67.78%。若仅把 R69 加速到原来的两倍快，在其他成本不变的条件模型下，全链约只快 1.033 倍。若三个重段均变为两倍快，条件模型的全链 elapsed 可减少约 33.89%；这不是已经实现的收益。

这些是共享资源下、多个数据契约的阶段墙钟耗时。累计约 108.67 小时是进程 elapsed 求和，不是整批等待时间，也不是独占 GPU 小时。尚无逐算子 profiler，不能把 67.78% 全部归因于教师。

已核实的计算差异包括：R38/R44/R46 每次更新使用 micro64 累积，完整 B256 要执行四个学生和四个教师微批前向；处理的样本总数没有因此乘四，但调度、检查和传输更频繁。R38 的教师还是较大的 R17。R38/R44 的零权重谱损失当前仍执行。这些是下一轮计时应分别拆解的对象。

## 3. 最大的新机会：同一学生也在重复调用教师

完整谱系的 `batches(n, rng)` 固定每个逻辑 epoch 247 次更新。源池遍历完就重新排列继续采样，而当前 epoch 的 received IQ 仍按物理 ID 固定。学生参数每步变化，仍须正常训练；教师权重固定，其同一输入的目标可以复用。

对源池大小 n，令 q=ceil(n/256)，(c,r)=divmod(247,q)，则每逻辑 epoch 曝光量为 c*n+min(256*r,n)，唯一输入数为 min(n,曝光量)。本次直接执行原索引生成函数，复算 35 条新谱系的全部 700 个逻辑 epoch，与上述计数逐项一致；没有打开样本数据。

| 数据契约与角色 | 源池样本数 | 每轮实际曝光 | 每轮唯一教师输入 | 可避免的教师样本计算 |
|---|---:|---:|---:|---:|
| F0，L-only | 6300 | 62332 | 6300 | 89.89% |
| label01，L-only | 630 | 51916 | 630 | 98.79% |
| label05，L-only | 3150 | 59850 | 3150 | 94.74% |
| m1-fixed，L-only | 1080 | 53432 | 1080 | 97.98% |
| m1-natural，LU | 12600 | 62432 | 12600 | 79.82% |
| m3-natural，LU | 37800 | 63144 | 37800 | 40.14% |
| 原 F0，LU | 63000 | 63000 | 63000 | 0% |

这里的“可避免”是按唯一输入缓存的理论样本计算量。学生依旧执行 247 次更新，保留重复样本、部分尾批、损失分母、批序和全部训练曝光。不能把减少学生曝光冒充缓存加速。

若整张登记矩阵的 35 条新谱系从头采用这种轮内教师缓存，五个 KD 阶段教师样本处理量可从 213614300 降至 89336900，减少 58.18%。其中 17 条 L-only 的教师样本量约减少 93.90%。这不是剩余任务的实时收益估计，不适用于已经完成的计算，也不是 GPU 时间减少 58.18%。

实现应优先按“教师 checkpoint、数据契约、输入视图、epoch、物理 ID”缓存目标。学生 seed 改变顺序不影响目标索引，但教师 seed 改变会改变目标，必须区分。同一 ID 下一 epoch 的 received 已改变，不能沿用上一轮目标。

对超过 63232 个样本的大源池，一个 epoch 不一定访问全部源池。应缓存预定会访问的 ID 或按需填充，避免预计算本轮根本不用的样本。

## 4. 多学生共用同一个 R65：另一类确定的重复

现有七消融乘三学生 seed 共 21 条。其中 `copy_no_KD/random_no_KD` 共 6 条没有教师前向；其余 15 条使用同一原 R65。

这 15 条每条都对原 63k 源池完成 E20，累计教师样本处理量为 18900000。缓存一个教师在全部合法 `(epoch,ID)` 上的结果后，唯一教师输入为 1260000，理论减少 93.33% 的重复样本计算。在保持 B256 加尾批的原生成分组时，对应教师前向约 74100 次降至 4940 次。

只存教师最后两个阶段即可同时满足这些行：coarse-only 取最后一阶段，其余 KD 行取最后两阶段。不要只存最终输出，也不要跳过教师生成这些输出所需的前置迭代。FP32 全 20 轮目标约 5.16 GB；单轮约 258.05 MB，约 246.1 MiB。

21 条历史训练成本 CSV 中，random-with-KD 三 seed 平均 1051.68 s，random-no-KD 为 747.41 s，相差 304.27 s。这是不同训练轨迹和共享负载下的 elapsed 对照，不是教师单独 profiler，不能宣称教师精确占 28.93%。

若一个学生训练时间中教师占比为 f，k 个学生共用目标，且假设缓存构建与一次教师计算等价、暂不计读取，则总加速模型为 `1 / ((1-f) + f/k)`。例如 f=30%、k=15 时，约为 1.389 倍，而不是训练快 15 倍。实际还要扣除缓存生成、读取、搬运、目标检查和调度成本。

该 21 行组已经完成，不能为证明新缓存再启动旧矩阵。上述复用用于后续匹配诊断与新任务；原结果保留。

## 5. 采用逐轮、有界缓存，避免全部教师常驻

推荐先做轮内缓存，再为确实被多学生消费的教师保存跨行缓存：

1. 教师就绪后，为当前 epoch 的唯一合法输入批量生成目标，学生仍按原索引顺序读取并更新。小源池优先放显存或内存，较大缓存采用分块读取和预取。
2. 只有一个消费者、且源池每轮恰好遍历一次时，先用图捕获等方式加速教师在线推理；完整离线缓存并没有减少教师样本数。它是否划算取决于批量效率和数据搬运。
3. 有多个消费者时，同一个缓存生成任务服务这些消费者。保留 FP32 目标；同一物理输入不因学生 seed 再运行教师。学生更新、优化器和随机数状态仍各自独立。
4. 多个不同教师分开管理。若确有空闲资源，可让教师生产下一块目标与学生训练重叠；需要测整体吞吐。把教师移到另一张卡不会自动减少计算量，也可能增加设备间或主机传输。

例：F0 L-only 的三阶段目标，单 epoch 约 38.71 MB，全部 E20 约 774.14 MB；label01 L-only 单 epoch 仅约 3.87 MB。相比之下，原 63k LU 教师三阶段单轮约 387.07 MB、全部 E20 约 7.74 GB。

若不加区分，把 35 条新谱系的五个 KD 教师、全部 20 轮目标都持久化，按实际会访问的唯一 ID 计，FP32 理论输出仍约 512.29 GB，不含索引。没必要为了单消费者的轮内复用保存全部历史 epoch。按当前阶段、当前轮和消费者需求保留即可。

已有推理优化可优先用于完全冻结教师：合并同步检查、保持中间轨迹的静态执行和图捕获。教师不需要反向，迁移比学生训练图直接；但当前推理入口只返回最终 IQ，不能原样替代需要多阶段目标的训练教师。重排算术或使用残差复用时仍要核对教师目标数值。

## 6. 冻结前缀与学生计算的界限

action 阶段可缓存 coarse 对当前 received 的输出。R17 阶段可缓存冻结 coarse/action 的上下文，但必须继续对当前可训练 prior 的输出执行作用算子和 CG，并保留关于其输入的反向传播。

action 的随机探针仍须按原 generator 和原顺序生成；可缓存的是固定网络输出和已有作用监督，不能把整项随机损失或学生计算缓存下来。教师缓存构建也不应消耗学生的随机数状态。

R38 及之后学生的 coarse、action 和 prior 是联合训练的。它们刚从教师复制时数值相同，更新后便会分叉；不能一直读取教师上下文代替学生上下文，也不能缓存学生恢复轨迹。这样做会改变现有机制。

教师缓存还须核对不同生成 batch/microbatch 下的 FP32 目标差异。GroupNorm 等逐样本结构有利于改变生成批量，但不等于 GPU 运算逐位相同。保持数值设置、按相同输入比较阶段输出和学生梯度，再做同预算训练及七景验证。不得通过降低目标精度或停止学生梯度来获得首版收益。

## 7. 如果未来确实有“多个教师共同指导同一步”

当前 DURA 没有这种同时多教师损失，不能把顺序谱系擅自改成集成教师。对于已经定义好的固定权重、多教师 IQ 平方误差，有一个严格的数学复用办法：

设 `L = sum_m w_m ||z-t_m||²`，权重独立于学生，`W=sum_m w_m>0`，`t_bar=sum_m w_m*t_m/W`，则：

`L = W*||z-t_bar||² + C`，其中 `C=sum_m w_m*||t_m||²-W*||t_bar||²`。

因此可预计算每个样本、每个对齐阶段的加权目标及常数项；学生端只计算一次平方误差。保留 C 可保持原 loss 记录，学生梯度不变。NMSE 要保留原 clean 能量分母和阶段平均方式。本次用独立合成数组验证了该恒等式及学生梯度恒等式；它不是实际 DURA 加速实验。

该方法不能省去每个真实教师首次生成目标，也不能消除不同上游教师的训练成本。若教师权重依赖学生、涉及教师选择或非平方损失，不能直接套用。阶段教师的输出不能跨训练段平均，教师参数也不能直接平均替代它们的预测。

## 8. 严格保持现有方法时的执行优先级

第一批验证应选择一个固定小源池和一段重阶段，比较原教师在线前向与同 epoch/ID 目标缓存；保持原学生所有更新。同步测教师独立前向、目标 gather、学生前反向、完整 epoch 和显存，确认实际缓存命中率。

第二批验证固定 R65 为多学生共享目标生成一次的完整成本，再评估冻结教师图捕获。最后才改学生的可微残差复用和训练图，以便定位梯度与性能变化来自何处。

八阶段依赖链中，同一契约的后段必须等待直接上游教师冻结；不同契约可以在既有资源预算内调度，但不能为了加并发停止健康任务或假定更多进程必然更快。拆成阶段级任务可改善排队和恢复，不会消除这些依赖。

当前协议明确禁止跨数据契约复用 checkpoint，L/LU 也须区分。即使两个标注率配置可能具有相同 IQ 并集，也不能仅凭样本数量或方法无 TX 标签便跨用教师。本分析不修改该协议、不合并现有训练行。

将八阶段换成直接教师蒸馏、减少阶段或轮数属于新方法研究，不属于本轮“保留现有机制”的执行加速。保持识别性能仍须冻结新权重后，按同一 F、同一默认头、七景全部预测固定及独立 truth-last 比较。教师构建时间、缓存空间及首用/复用成本均单列。

计算依据与可复查数值见 [教师成本分析数据](analysis/dura_teacher_costs_20261022.json)。全部采样复算和缓存成本是计划/代码推导；阶段耗时来自已有完成元数据，本文不声称新的训练提速已实现。
