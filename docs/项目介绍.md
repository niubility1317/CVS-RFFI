# CVS-RFFI/CV-SincNet项目介绍

版本：2026-08-01
当前数据协议：`p2_min_v1`

## 1.文档定位

本文面向论文读者、项目评审者和后续研发人员，说明CVS-RFFI/CV-SincNet的研究动机、实际卫星场景、Phase1—Phase3任务边界、Phase2数据协议、当前能力范围和后续研究路线。

本文是项目介绍和研究路线说明，不替代本地治理源文件`项目.md`。涉及科学场景、数据权限、接收机与发射机集合、Phase1/Phase2边界、Stage2-A/B/C权限及正式声明语义时，以本地`项目.md`为唯一来源；活动方法、性能目标、实验矩阵、资源预算和具体结果分别由目标文档、方法设计与实验报告管理。Git公开协议见[PROJECT_PROTOCOL.md](PROJECT_PROTOCOL.md)。

## 2.一句话项目概述

CVS研究天基射频指纹识别中的弱标注跨接收机域泛化，以及模型部署到未见卫星接收机域后，如何利用少量合法标注的目标域样本完成旧类适应与新类注册；后续Phase3将进一步研究无标签未知信号的初步拒识、多源协同推理、可信标签形成及其向Stage2-C注册流程的安全交接。

项目采用“地面训练、天上部署”的总体架构：

```text
Phase1：地面弱标注跨接收机域泛化
    ↓封存不可变deployment bundle
Phase2：目标卫星接收机域适应与注册
    ├─Stage2-A：零target标签参考/诊断
    ├─Stage2-B：旧类K-shot适应与校准
    └─Stage2-C：旧类适应+有标签新类注册
    ↓安全扩展
Phase3：未知拒识+多源关联+协同确权+注册授权
    ↓形成新的合法support注册事件
回到Stage2-C：注册已确权的新类并持续识别
```

这里最关键的边界是：**Stage2-C解决“已经获得可信标签后如何注册”，Phase3解决“标签尚不存在时如何发现并确立标签”。**两者共同构成完整开放世界生命周期，但当前CVS尚未完成Phase3闭环。

## 3.为什么天基系统需要射频指纹识别

低轨卫星通信正从少量专用链路演变为大规模、异构且频繁切换的非地面网络。3GPP Release 17首次给出规范性的NTN要求，Release 18继续研究网络核验终端位置、NTN-TN与NTN-NTN移动性及业务连续性；Starlink公开说明，一个美国用户终端通常能够看到数十颗卫星，并会在每分钟内多次切换服务卫星；Iridium也在66颗LEO卫星基础上推进标准化NB-IoT和Direct-to-Device服务。[3GPP NTN概述](https://www.3gpp.org/technologies/ntn-overview)、[Starlink Beam Switching](https://starlink.com/tv/updates/starlink-beam-switching)、[Iridium NTN Direct](https://www.iridium.com/services/iridium-ntn-direct)

这些系统扩大了无线信号的观测范围，却没有自动解决“当前信号究竟由哪一部物理射频设备发出”。密码学认证验证的是密钥或凭据，协议地址表示的是逻辑或行政身份，地理定位回答的是发射机位于何处，调制识别判断的是信号类型。账号、密钥、ICAO地址、MMSI或DCP地址均不必然与当前射频前端一一对应：凭据可能被复制，协议地址可能被错误配置、重放或冒用，合法设备也可能在账号不变的情况下更换功放、本振、应答机或整套射频模组。[3GPP TS 33.501](https://portal.3gpp.org/desktopmodules/Specifications/SpecificationDetails.aspx?specificationId=3169)、[FAA ADS-B FAQ](https://www.faa.gov/air_traffic/technology/equipadsb/resources/faq)、[ITU-R M.585](https://www.itu.int/rec/R-REC-M.585/en)

射频指纹识别利用发射机功率放大器非线性、I/Q不平衡、本振频偏、相位噪声、DAC误差和发射瞬态等硬件差异，为现有身份系统增加一条面向物理射频链的被动证据。它不替代密码学认证，也不直接提高链路预算或香农容量；其现实价值在于核验逻辑身份与物理发射机是否一致、辅助发现地址冒用和凭据克隆、关联跨时段重复出现的干扰源、降低新设备全量重训练成本，并为跨卫星切换和设备维护提供持续身份证据。

## 4.科学问题与观测模型

目标卫星接收到的I/Q并不是纯净的发射机指纹，而是发射机、传播信道和接收机链路共同作用的结果：

```text
x = R_d(H_d * T_y(s)) + n
```

- `T_y`表示发射机`y`的硬件非理想性，是身份来源；
- `H_d`表示传播或星地信道，是域扰动；
- `R_d`表示接收机`d`的链路响应，是跨接收机偏移；
- `n`表示噪声。

WiSig包含1000万数据包、174个Wi-Fi发射机、41台USRP接收机和跨一个月的4次采集。其研究表明，仅改变接收机或采集日期就可能显著降低识别性能，说明同接收机闭集分类准确率不能代表天基跨接收机部署能力。[WiSig](https://arxiv.org/abs/2112.15363)

CVS因此同时研究两个问题：

1.地面端如何在标注率不超过0.1、接收机存在差异的条件下，学习尽量保留`T_y`并抑制`R_d`与`H_d`的身份表征；
2.部署端如何在`R_t∩R_s=∅`的目标卫星接收机域，仅使用固定LEO弱信道接收IQ、合法K-shot support和不可变Phase1 bundle，完成旧类适应及新类注册。

## 5.集合、身份和阶段定义

接收机集合满足：

```text
R_s = source training receivers
R_t = target receiver domain
R_t ∩ R_s = ∅
```

发射机集合满足：

```text
Y_old = Phase1已见发射机
Y_new = Phase1未见、在Phase2获得合法support并完成注册的发射机
Y_unknown = 尚未注册的发射机

Y_old ∩ Y_new = ∅
Y_unknown ∩ (Y_old ∪ Y_new) = ∅
```

在Phase1出现过的发射机进入Phase2后只能属于`Y_old`，不能因目标接收机或信道发生变化而被重新命名为新类。`Y_new`与`Y_unknown`的区别也不是“模型是否认识”，而是前者已经具有合法注册support，后者尚未完成注册。

## 6.Phase1：地面弱标注跨接收机域泛化

Phase1属于weak-label/semi-supervised source-domain DG，不是部署阶段few-shot learning：

```text
L_s = {(x_i,y_i,d_i): receiver(x_i) ∈ R_s}
U_s = {(x_j,d_j): receiver(x_j) ∈ R_s, y_j hidden or unavailable}
rho_label = |L_s| / (|L_s| + |U_s|) ≤ 0.1
```

当前统一划分语义为相对source全池`0.07/0.63/0.30`：有发射机标签训练集、无发射机标签训练集和互斥source validation。三部分都不得包含`R_t`。Phase1可以使用source clean与卫星信道增强视图训练，但这些数据和样本级派生状态不会因此获得Phase2访问权限。

Phase1最终输出与checkpoint共同封存的不可变deployment bundle。Phase2不能回读地面数据重新构造原型、特征缓存或训练统计；唯一允许的扩展是事先封存、只读、不可逆且符合`项目.md`约束的int8多样本聚合模型知识。

## 7.Phase2的Stage2-A/B/C及其现实场景

### 7.1Stage2-A：零target标签参考与诊断

|项目|定义|
|---|---|
|可用target信息|无target发射机标签；可有无标签LEO接收IQ|
|任务|测量零标签条件下的目标域参考表现、域偏移和未注册状态|
|现实场景|卫星刚进入新区域、刚启用新接收载荷或尚未获得目标终端标签时，先评估现有地面模型在目标接收机域的直接迁移能力|
|可以声明|zero-label target-domain reference/diagnostic|
|不可声明|旧类few-shot适应、新类身份准确率、完整未知拒识能力|

Stage2-A不是自动发现新身份的解决方案。它回答的是“没有target标签时，现有表征在目标卫星域表现如何”，并为后续Stage2-B/C提供参考底线。真正面向未知类的拒识、匿名跟踪和语义确权属于Phase3。

### 7.2Stage2-B：目标域旧类适应与校准

|项目|定义|
|---|---|
|可用target信息|`Y_old`每类K个合法target support标签|
|任务|利用少量目标卫星接收样本校准旧类在`R_t`中的接收机和信道偏移|
|现实场景|运营方已知一批历史终端或卫星载荷身份，但这些设备首次由新卫星接收机、替换载荷或新网关链路观测|
|可以声明|旧类目标域适应、校准及注册前后旧类变化|
|不可声明|新类注册性能、seen-new identity accuracy|

典型例子是同一批合法终端由卫星A切换到具有不同射频响应的卫星B。终端身份并未改变，改变的是接收域。Stage2-B使用旧类K-shot support修正目标域偏移，不把旧类重新定义为新类。

### 7.3Stage2-C：旧类适应与有标签新类注册

|项目|定义|
|---|---|
|可用target信息|`Y_old∪Y_new`每类K个合法target support标签|
|任务|在同一目标接收机域同时完成旧类适应与新类注册|
|现实场景|新终端合法入网、新厂商模组加入网络、航空器或环境平台更换射频设备、星座补充新卫星或载荷|
|可以声明|`old_acc`、`seen_new_acc`、`H_old_new`、遗忘和混淆|
|不可声明|把尚未确权的`Y_unknown`直接当作`Y_new`，或把未知拒识结果替代新类注册结果|

Stage2-C假定标签已经通过运营方登记、受控测试、维护记录或其他外部流程获得。当前CVS研究的重点是：标签存在以后，如何以少量目标域样本注册新发射机，同时保持旧类能力。Stage2-C本身不负责从无标签突发信号推导现实语义身份。

### 7.4三阶段关系

|问题|Stage2-A|Stage2-B|Stage2-C|
|---|---|---|---|
|是否有target标签|无|仅旧类|旧类和新类|
|是否更新部署状态|否，仅参考/诊断|由旧类support更新|由旧类与新类support适配和注册|
|是否识别seen-new|否|否|是|
|是否解决未知类语义确权|否|否|否，标签是输入前提|
|核心现实作用|测量直接部署风险|跨接收机旧类校准|受控新设备入网|

## 8.Phase2最小数据协议`p2_min_v1`

### 8.1单物理样本只能形成一个LEO接收观测

每个clean/raw物理I/Q记录在进入Phase2前只允许进行一次随机LEO弱信道叠加：

```text
received_i = H(c_i,seed_i)(clean_i)
c_i ∈ {leo_clear_weak,leo_low_elev_weak,leo_rain_weak}
```

一个稳定`physical_sample_id`只能绑定一个场景、一个随机信道实现和一份固定`received_i`。禁止复制同一物理样本并生成多个LEO场景或随机信道副本。三种场景的物理样本集合两两不交；单场景内support与query的物理样本也必须不交。

### 8.2K-shot表示独立物理样本

每类K-shot必须由K个互不重复的物理support样本组成。同一固定接收IQ经过均衡、裁剪、归一化、FFT或其他数学变换后仍然只是一个物理样本，不能增加K。

support的计算view可以参与适配和注册。query及其所有view仅用于当前样本推理，不得更新模型、原型、阈值、温度、门控、候选选择、早停或回滚状态。

### 8.3Phase2只读取最小合法输入

Phase2运行时只允许读取：

1.不可变Phase1 deployment bundle；
2.已经一次验证并封存的固定LEO接收IQ capsule；
3.当前row的support标签、注册类别表和不含query真值的split；
4.与数据无关的算法配置。

Phase2不得读取clean/raw/source样本、source cache、source replay、样本级source feature、clean派生logit或prototype，也不得访问能够影响决策的外部source状态。

### 8.4每个query独立面对全部已注册类别

预测阶段禁止使用query真值、真实old/new/unknown角色、真实batch类别数、类别配额、标签排序、分块或跨query全局重排。预测artifact必须先冻结，独立scorer之后才能依据opaque query ID连接真值；评分结果不得回流到适配、注册、阈值选择或重跑决策。

### 8.5一次验证、跨方法复用

数据builder完成唯一观测、物理ID、集合互斥和禁止成员检查后，输出：

```text
protocol_schema = p2_min_v1
phase2_data_status = VALIDATED_ONCE
capsule_id = <content identity>
split_id = <receiver/TX/scenario/K/support-query identity>
single_leo_observation = true
clean_source_runtime_access = false
query_fit_access = false
query_decision_policy = per_sample_all_registered_classes
```

只有固定接收IQ字节、物理ID、receiver/TX集合、scenario分配、K、support/query划分或协议schema发生变化时才重新验证。候选方法、adapter、超参数、epoch、原型规则、模型状态或资源预算变化不会使数据capsule失效。

## 9.当前CVS已经覆盖什么，尚未完成什么

当前CVS已经形成了“地面弱标注表征学习—目标卫星域零标签诊断—旧类少样本适应—有标签新类注册”的科学协议和方法研究主线。具体算法是否达到性能目标，必须由对应实验报告和完整同row证据判定，不能仅依据代码存在或场景定义宣称完成。

|能力|当前定位|声明边界|
|---|---|---|
|Phase1弱标注跨接收机DG|当前研究组成|WiSig/ManySig是地面代理数据，不是真实卫星数据|
|Stage2-A零标签目标域参考|协议已定义，可作诊断|不是完整未知拒识系统|
|Stage2-B旧类目标域适应|Phase2研究组成|只能声明旧类适应与校准|
|Stage2-C有标签新类注册|Phase2主线|必须同时具有合法old/new support并报告旧类保持|
|初步未知拒识|尚未形成完整主线闭环|不得把已有零标签参考或零散unknown指标写成Phase3完成|
|多源信号关联与可信标签生成|尚未实现|当前Stage2-C直接接收合法标签，不负责产生标签|
|协同推理和证据冲突消解|Phase3计划工作|算法家族、数据接口和门槛仍需后续冻结与验证|
|与认证、定位、AIS/ADS-B、维护系统联动|场景设计与后续工程方向|不能声称已经进入真实运营系统|
|真实在轨验证|尚未完成|LEO弱信道模拟只属于物理启发压力代理|

因此，当前CVS完成的是开放世界身份生命周期的中段，而不是全部：

```text
当前重点：可信标签已存在
合法support → 目标域适应 → 新类注册 → 旧/新类联合识别

尚未完成：可信标签尚不存在
未知检测 → 匿名实体关联 → 多源协同推理 → 语义确权 → 注册授权
```

## 10.Phase3：未知拒识、多源协同推理与可信标签形成

### 10.1Phase3的目标

Phase3拟解决卫星首次接收到无标签突发信号时的完整前置问题：

1.判断该信号是否无法由当前注册身份库可靠解释；
2.把跨卫星、跨轨道和跨时段观测关联为稳定匿名实体；
3.联合协议、位置、轨迹、认证、调度、外部传感器和人工调查证据推断候选身份；
4.评估证据可靠性、相关性和冲突，形成可审计可信标签；
5.在达到注册门槛后触发新的受控K-shot采集，而不是直接用未知query更新Stage2-C；
6.把封存的注册凭证和新support交给Stage2-C，完成正式新类注册。

Phase3与Stage2-C的关系可以表示为：

```text
无标签突发信号
    ↓
初步拒识/不确定性检测
    ↓
跨星多次观测关联为anonymous track
    ↓
多源协同推理与冲突消解
    ↓
L3/L4可信标签+注册授权
    ↓
重新采集K个独立物理support
    ↓
生成新的capsule/split并完成一次数据验证
    ↓
Stage2-C注册为seen-new
```

### 10.2拟接入的多源证据

|证据层|示例|能够证明什么|不能单独证明什么|
|---|---|---|---|
|运营方/监管登记|终端序列号、ICAO、MMSI、DCP地址|逻辑身份已被合法分配|当前信号一定来自登记硬件|
|密码学认证|5G-AKA、EAP-AKA′、专网证书|发射端持有合法凭据|凭据没有被复制或转移|
|资源和调度|时隙、频率、波束、查询响应|信号符合被分配的接入机会|符合资源分配即等于真实设备|
|位置与轨迹|TDOA/FDOA、MLAT、GNSS、星历|发射源位置和运动连续性|同一位置只有一部设备|
|协议与行为|ADS-B/AIS、呼号、发送周期、业务模式|声明身份和行为是否一致|协议字段未被伪造|
|独立传感器|雷达、SAR、光学、地面监测|信号与现实目标是否关联|目标上具体哪部射频链发射|
|维护与现场确认|维修日志、设备序列号、现场拆机|物理设备及硬件状态|远程运行期间始终没有变化|

ITU-R SM.2355-2说明，两个或更多近编队卫星可以联合到达时间差和到达频率差估计地面发射源位置。[ITU-R SM.2355-2](https://www.itu.int/pub/R-REP-SM.2355-2-2023)HawkEye 360在2026年公开的NOAA GOES干扰案例中，使用80次卫星采集在约一周内缩小厄瓜多尔基多附近的干扰区域，随后由当地机构现场确认并拆除一套停用模拟无线电设备。[HawkEye 360 GOES干扰案例](https://www.he360.com/resources/geolocating-rf-interference-to-the-noaa-goes-satellite-system/)这个案例说明了“天基发现与定位—地面确权—后续注册”的业务链条，但企业案例本身不能作为CVS算法性能证据。

### 10.3拟研究的协同推理算法

Phase3不预先锁定单一算法。后续候选可包括：

- 基于能量、距离、密度、EVT或集成不确定性的初步未知拒识；
- 基于时频、轨迹、位置和指纹相似度的跨过境匿名实体关联；
- 可靠性加权的贝叶斯证据融合或因子图推理；
- 以信号、实体、传感器和登记记录为节点的图协同推理；
- 面向证据冲突、缺失和来源相关性的注意力或可信度校准；
- 人机协同复核和现场确认后的受控标签升级。

协同推理的研究重点不是把多个分数简单相加，而是显式处理三类问题：不同证据识别的对象并不相同；同源证据不能重复计数；强冲突不能被大量弱一致证据掩盖。

### 10.4建议的标签置信等级

以下L0—L4等级是项目拟采用的审计方案，不是现有行业标准：

|等级|含义|处理方式|
|---|---|---|
|L0|只观测到未知信号|拒识、聚类和匿名跟踪|
|L1|只有自报ID或单一登记来源|形成候选身份，不注册|
|L2|至少两条相对独立证据一致|继续采集和人工复核，可作探索性分析|
|L3|登记或认证、受控时间窗和独立采集同时成立|达到Stage2-C正式注册的建议下限|
|L4|现场、维护或设备序列号确认具体硬件|作为高可信注册和审计基准|

Phase3输出不应只有类别名称，还应包含：

```text
entity_track_id
candidate_physical_identity
logical_identity_aliases
label_confidence_level
evidence_source_ids
evidence_independence_summary
time_location_consistency
hardware_state_and_validity_interval
conflict_flags
human_or_field_review_status
registration_authorized
```

### 10.5Phase3到Stage2-C的安全接口

多源传感数据、协同推理图和未知query不直接进入Phase2 predictor。Phase3只在外部完成确权，并输出不可变注册凭证。随后创建新的受控注册事件：

1.冻结`phase3_label_evidence_id`和标签有效期；
2.为获批身份重新采集K个独立物理support样本；
3.保留此前未知query作为不可变检测证据，不将其追溯改成训练support；
4.因support物理ID或support/query划分改变，生成新的`split_id`并执行对应数据验证；
5.Stage2-C仅读取批准后的类别标签、注册类别表、固定接收IQ和最小协议句柄；
6.注册完成后，每个后续query仍独立面对全部已注册类别，且不能在线污染原型。

这一接口保证Phase3扩展不会破坏`p2_min_v1`的query零更新、无clean/source访问和support/query物理隔离原则。

## 11.注册完成后如何配合现有卫星系统

新类完成Stage2-C注册后，RFFI应作为物理身份因子进入跨层决策，而不是取代现有认证系统：

|上层结果|RFFI结果|建议处置|
|---|---|---|
|凭据通过|指纹一致且高置信|正常接入并记录持续验证证据|
|凭据通过|指纹持续不一致|增强认证、限权、检查凭据克隆或硬件更换|
|凭据通过|低质量或不确定|继续采集，不因单次低质量信号拒绝|
|凭据失败|与历史物理设备一致|不得自动授权；检查凭据过期、网络故障或账号变更|
|凭据失败|指纹也不一致|隔离并进入Phase3未知调查|
|无密码学能力|多源证据和RFFI一致|用于风险分级与辅助认证，不宣称等价于强密码认证|

在Starlink式频繁切换场景中，系统可以在初次合法入网时建立物理注册，随后由不同卫星独立提取接收机无关身份表征，联合认证上下文和位置连续性判断切换前后是否仍为同一终端。在NOAA GOES DCS场景中，DCP地址、指定频率和发送时刻可以与RFFI结合，区分合法设备更换、设备老化和地址冒用。在ADS-B、AIS和Cospas-Sarsat等安全关键系统中，RFFI只能作为异常提示或辅助证据，不能因一次指纹不匹配就丢弃航空监视目标、船舶安全信息或遇险信号。[NOAA GOES-R用户系统](https://goes-r.noaa.gov/users/user-systems.html)、[Aireon空间ADS-B](https://aireon.com/its-just-ads-b/)、[NOAA 406MHz信标](https://www.sarsat.noaa.gov/emergency-406-beacons/)

## 12.Phase3建议评价指标

|环节|核心问题|建议指标|
|---|---|---|
|未知拒识|能否拒绝未注册发射机且保持旧/新类性能|unknown FAR、AUROC、FPR95、已注册类保留率、defer率|
|匿名关联|多次观测能否归并为同一实体|pairwise F1、track purity、ID switch、跨星关联准确率|
|候选身份推理|真实身份是否进入候选集|Top-k recall、平均候选集大小、校准误差|
|可信标签形成|标签是否正确且证据充分|L3/L4标签精度、错误注册率、证据覆盖率、冲突发现率|
|Stage2-C回流|注册后能否识别新类并保持旧类|`seen_new_acc`、`old_acc`、`H_old_new`、逐类遗忘|
|系统收益|是否改善实际处置|注册时延、增强认证触发精度、干扰归因时间、人工复核成本|
|资源开销|能否在星上或网关运行|模型大小、峰值内存、推理时延、能耗、状态字节数|

Phase3的成功不能只由unknown AUROC定义。只有“未知检测—正确关联—可信标签—合法注册—注册后旧/新类联合表现”全链条同时成立，才能声明开放世界身份生命周期得到闭合。

## 14.可声明范围

项目可以声明：

- 研究弱标注跨接收机域泛化；
- 研究LEO弱信道压力下的旧类少样本目标域适应；
- 研究具有合法K-shot support的新类注册与旧类保持；
- 将未知拒识、多源协同确权和可信标签形成定义为Phase3后续方向；
- 研究Phase3向Stage2-C的协议安全接口。

项目当前不能声明：

- WiSig/ManySig是真实卫星数据；
- LEO模拟等价于真实在轨验证；
- Stage2-A已经完成未知类拒识；
- Stage2-C可以在无标签条件下自动获得新类语义身份；
- 当前系统已经完成多源协同推理或可信标签自动生成；
- unknown拒识指标可以替代`old_acc`、`seen_new_acc`和`H_old_new`；
- RFFI可以替代密码学认证、监管登记、地理定位或现场调查；
- 单次高准确率足以证明真实卫星系统部署成功。

## 16.项目最终目标

CVS的最终目标不是构造一个脱离系统上下文的射频分类器，而是形成一条可审计、可扩展且协议隔离的天基物理身份链：地面端学习跨接收机稳定表征；Phase2在合法support存在时完成目标域旧类适应和新类注册；Phase3在标签缺失时完成未知拒识、匿名关联、多源协同推理和可信标签授权；注册后的射频指纹再与认证、位置、协议、调度和维护系统联合，为持续接入、跨星切换、干扰归因和设备生命周期管理提供物理层证据。

在这一总体目标下，当前工作的准确定位是：**Phase2主线正在解决“如何适配和注册”，Phase3将继续解决“何时拒识、如何确权以及何时允许注册”。**
