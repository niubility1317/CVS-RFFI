# DURA 训练加速分析

日期：2026-10-22。范围：保持现有恢复机制、数据权限和识别性能，分析训练执行优化。状态：`CODE_ANALYZED / NOT_BENCHMARKED`；本次未修改训练器、未启动训练、未产生或替换权重。以下预期收益均不属于实测加速结果。

后续深入分析见 [多教师与重复采样成本分析](DURA_MULTI_TEACHER_TRAINING_ANALYSIS.md)。阶段耗时和原采样器复算表明，应优先处理小源池的轮内教师重复计算及 R38/R44/R46，再评价末段 R69 的优化收益。

## 1. 结论与固定边界

优先减少 CPU/GPU 同步、输入复制及无效损失计算，再验证可微物理求解的残差复用，最后考虑训练图捕获。不能把推理的约 9.1 倍收益直接外推至训练。

保持 DURA v1.0 的两次 prior、四次 CG、实线性作用及其真实伴随、反射边界、逐样本噪声方差、所有现有学生组件联合更新和共享参数关系。保留最终 IQ NMSE、0.05 倍多尺度谱误差、阶段对齐蒸馏及其日程。冻结教师继续提供与原始样本和 epoch 匹配的目标。

首版保持 FP32、TF32 关闭、原 AdamW、裁剪阈值、学习率、随机数消耗、批次次序、有效批量、微批量和更新次数。不得通过少训练、少用 U、减少 CG、停止组件梯度、取消蒸馏或降低精度获得“同机制”加速。

默认 `dura_v1` 权重和现有正式识别结果保持原定义。新训练得到的权重，即使结构和方法相同，也要独立冻结验证后再判断性能，不能因少量梯度检查通过而宣布七景性能保持。

## 3. 第一优先级：消除执行等待与重复准备

### 3.1 合并 GPU 数值检查和日志回传

原 `experiments/pamf_r65_four_route/training.py` 每批在损失有限性检查、四项损失的 `float(...)`、梯度裁剪有限性判断及裁剪计数处读取 GPU 标量。作用算子的构造和每阶段 `weighted_map` 还会把有限性、方差正值判断转换为 Python 布尔值。教师和学生均走这类检查。

这些位置会要求 CPU 等待 GPU。它们是已定位的同步点，具体占时仍需 profiler。当前完整谱系训练器的日志项较少，但作用算子和物理求解中的同步仍存在，且部分阶段每次更新执行四个微批次。

建议把日志统计留在设备上，轮末一次回传；形状、类型等静态检查仍在入口执行。数值检查改为设备侧归并，并在更新前检查，或使用经过负测的设备侧断言。必须保留 NaN/Inf、非正方差及非法输入导致技术失败的行为，不能简单删除保护或仅在训练结束检查。

第一版不改变正常样本的模型算术顺序和优化器调用方式。日志累加即使改为设备侧，也要避免把变化带入实际梯度和优化器。

### 3.2 缓存输入、减少 CPU 复制并重叠搬运

当前完整谱系的 `CacheView.batch` 已缓存 mmap 文件句柄，不能把它误诊为每批重新打开全部文件或在线重新生成信道。实际仍有 CPU 随机 gather、批次拼接、`io.tensor` 的额外数组复制，以及同步 `.to(device)`。

63000 条 FP32 IQ 的 clean 和单 epoch received 合计 258048000 bytes，约 246.1 MiB。显存允许时，可在 epoch 开始一次加载，随后按原 NumPy 生成的索引进行设备 gather；不要换成另一套随机排列。更大的契约或阶段使用有界 pinned-memory 缓冲和双缓冲预取。两种方案均须保持物理 ID、epoch、角色和批次顺序逐项对应。

报告 epoch 准备成本、完整 epoch 墙钟时间和峰值显存，不能只报告已经在显存中的一步时间。其他 owner 的健康进程和资源上限保持。

### 3.3 取消权重为 0 的谱损失计算

完整谱系 `g_lineage.objective` 在 `r38/r44` 的谱损失系数为 0，但当前表达式仍先执行 `spectral_error`，构造三个尺度的 FFT 和相关反向分支，再乘 0。可以按固定 stage 跳过这项无效计算。

本项只适用于这两个现有系数为 0 的上游阶段。DURA 最终 `r69` 的谱损失系数为 0.05，必须保留；其他有谱损失的阶段也保持。对有限输入核对损失、所有参数梯度和优化器一步结果，并保留有效损失的非有限检查。

### 3.4 缓存常量与 clean 端谱目标

Hann 窗、反射索引、固定尺寸模板可以按设备、精度、形状缓存。`spectral_error` 中 clean 分支没有梯度，且同一 clean IQ 在多个 epoch 和阶段重复出现，可以按合法源物理 ID 缓存其固定谱目标与归一化尺度。

63k 条 clean 的三个尺度功率/目标数组约 274.2 MB，另计尺度和索引。缓存必须保留原周期 Hann、FFT 归一化、尺度钳位和浮点精度。批量形状变化也可能影响数值，仍需核对，不能仅凭公式相同承诺逐位一致。

## 4. 第二优先级：复用冻结教师计算

教师输出由冻结权重、输入及运行设置决定，可以生成一次后按原 epoch 和物理 ID 读取。这样保留蒸馏目标，但把训练循环内的教师前向改为缓存读取。

单次新增 E20 的 received 每轮不同，需要生成全部 126 万条教师结果。仅保存对齐的两个阶段，FP32 IQ 需 5160960000 bytes，约 5.16 GB；保存三阶段约 7.74 GB，均不含索引。缓存构建耗时和 I/O 必须计入首次训练总成本。

对于原 63k 源池、每轮完整遍历一次且只训练一位学生的情况，缓存不会凭空免除教师计算，可能收益不大；同一冻结教师、同一合法输入被多条蒸馏行复用时更有价值。后续分析补充：小源池在固定 247 步逻辑 epoch 内反复遍历，单个学生也有显著教师计算去重空间，不能套用上述 63k 情况的判断。21 条消融中 `copy_no_KD/random_no_KD` 本来就不执行教师前向，不能给这些行计算教师缓存收益。不同 seed 的教师、不同数据契约、L 与 LU 权限、不同 epoch 输入均不能混用。

阶段损失需要中间轨迹，不能只缓存最终输出。缓存生成的批量/微批量和精度须核对原数值；首次与复用时分别报告总时间及缓存空间，不把教师当作免费资源。

## 5. 第三优先级：可微残差复用与训练图

### 5.1 先保持算术顺序，再检验残差复用

已有推理静态程序可以提供去除 Python 数值分支的参考，但现有推理入口要求冻结参数，并使用 `inference_mode`，不能直接作为训练入口。训练还必须返回两阶段输出供蒸馏使用。

原求解先构造 `A*(v^-1(y-Ap))`，再减去初值偏差的正规项。对每个观测窗口的标量实方差，数学上可改写为 `v^-1 A*(y-Ax0) - (x0-p)/tau^2`，复用当前阶段已算出的创新项。原固定版推理的 FFT/IFFT 从 43 次降至 27 次说明前向存在冗余，但这不是训练实测收益。

在训练中改写会改变浮点运算顺序和反向图；`x0`、`p`、作用算子及方差都可能依赖学生参数。不得 detach 创新项、作用响应、方差或初值来换速度。需要逐项核对输出、阶段损失、输入及全部可训练参数梯度、裁剪范数、AdamW 更新和短程训练轨迹。保持真实伴随、反射边界和四步 CG。

### 5.2 最后捕获训练图或选择性编译

训练图覆盖的是学生前向、损失、反向及可能的优化器，与现有推理图不同。先独立测前反向捕获，再判断是否捕获 AdamW；学习率和蒸馏权重需可更新，避免捕获后固定为第一步数值。

原始 63k 契约需处理 B256 和尾批 B24；其他契约、L-only 循环和微批累积有不同形状。必须保持每次更新的真实分母。`r38/r44/r46` 的 micro64 累积、共享参数，以及 `r65` E10 的结构切换和优化器重置都需要对应处理。不能复用切换前的参数地址或错误图。

`torch.compile` 可从局部 CNN/逐元素片段试起；复数 FFT、动态 Python 作用对象和散射反向的支持依环境实测。报告编译/预热开销和整个训练段时间，不只选稳态最快的一段。首版不引入 AMP/BF16/TF32、优化器替换或跨 GPU 扩大全局 batch。

## 6. 验证与实施顺序

1. 在独立不可覆盖诊断中，比较同机同卡、同输入、同父权重、同批序的原实现与候选；先只用合法源域或无 query smoke。分别测数据准备/传输、教师、学生前反向、损失、裁剪/更新和同步等待。当前固定权重不动，正在运行的队列不热改。
2. 首个候选仅包含日志/检查同步优化、输入准备和常量缓存；完整谱系另对 `r38/r44` 加入零系数分支跳过。用输出、全部梯度及更新对照确认影响，再在相同资源条件下交替计时，报告峰值内存和整个 epoch 时间。
3. 教师缓存按首次构建与多行复用的总成本单独评估；可微残差复用与训练图分别验证，避免收益和数值变化混在一起。
4. 对新训练路径固定一条同父权重、同 seed、同 E20/4940 的完整对照；不根据 target 结果调整实现或选择性重跑。需要评估完整谱系时，逐阶段匹配原固定预算，不能只测 r69 就宣称八阶段全部加速。
5. 训练完成后按预登记连接同一冻结 F 和原默认头，七景各 168000 条，全部预测固定后独立 truth-last。逐景报告正确数差、clean 损伤及 TX/RX/day，不用平均值掩盖下降。以保持原识别性能为目标；未做该检查时只报告执行/数值结果。

历史 DURA＋原 F50 的七景和时延，是该原始配对的证据。采用现默认 PAMF-T1-E50 时，原/新恢复器必须共同接同一 T1 权重进行匹配比较，不能直接挪用原 F50 指标。冻结教师缓存和训练诊断均不得读取 TX 真值、F 输出或目标 IQ 来优化 G。

结论边界：本分析确认了代码中的同步点、复制、零权重计算及可复用目标，没有实测确认它们各自占多少时间。建议的首版属于保留机制的执行优化；新的训练加速倍数和识别性能保持须由上述匹配结果证明。
