## 已核对的直接正确性

1. **输入和继承边界。** OSC 入口复用原生冻结编码器产生的四相位 identity160/FFT96 缓存，核对实际 checkpoint SHA、seed、旧类顺序、final200/from-scratch provenance、capsule、生产配置、完整相位顺序、float32 schema、物理 ID 及字节数。生产特征的算法配置与 OSC 自身算法配置分开校验，不能仅凭相同 shape 接受缓存。入口不加载 BNNA 适应器、训练 state、预测或成绩，不重新载入 checkpoint，也不执行源数据 loader。旧模型包仍按完整训练 checkpoint 文件计量，部署状态和新增模型传输保持未知。

2. **完整物理 support。** 类内 medoid 的目标为四个循环位置最小距离之和；对齐方向与设计中的 `(v+s) mod 4` 一致，medoid 自身 shift 固定为 0。物理 ID 的稳定排序决定精确并列。模板不再归一化；四视图属于一个物理样本，均不增加 K。

3. **协方差和解析编译。** 经验残差按 `4*C*(n-1)` 平均，而收缩自由度严格为 `nu=C*(n-1)`、`lambda=256/(nu+256)`。K1、零能量和预定近零残差分支使用单位形状；其余使用共享收缩形状，无旧新类分组权重。Cholesky 解算得到 `W=256*Q^-1*mu`，偏置为 `-sum(mu*W)/8`；编译分数中的交叉项系数为 `1/4`。删除的 query 二次项对全部类别与循环位置相同，因此不改变 softmax、NLL 或 argmax。没有额外温度拟合、候选网格或降级替代方法。

4. **fold 全流程隔离。** 每个 fold 的 `_fit_train` 只接收排除 held physical ID 后的数组和标签，重新选择 medoid、shift、模板、协方差、Cholesky 及 W/b。不等长 fold 使用实际 n；最终全 support 重新解析拟合。点式特征归一化可在切 fold 前执行，未使用跨样本统计。旧新成员身份只进入 OOF 分组诊断，不进入拟合或 query 公式。

5. **K1 和 CV 权限。** K1 不调用 OOF 诊断，无 holdout。K≥2 固定 `min(K,3)` 个物理 fold，记录每个 support 的一次 OOF NLL/预测。唯一公式始终固定，OOF 不影响最终公式或参数；日志中的 `candidate_count=1` 表示唯一公式，`selection=none_cv_diagnostic_only`，不是候选搜索。优化器步数为 0；epoch、学习率和梯度为 null 并解释原因。

6. **query 与持久状态。** query 按单个物理样本面对全部注册类计算四循环 log-mean-exp；没有跨 query 拟合、全局排序或配额。核心保持输入类表顺序，预测和 scorer 均按物理类 ID 处理精确并列。只读 W/b 共 `8200*C` 字节，C=26 时为 213200 字节；类表、审计信息、临时矩阵、缓存容器和进程 RSS 分开记录。评分不修改状态。

7. **启动、输出和发布依赖。** predictor CLI 与 runner 的 `--orbit-features` 路径一致，缓存来源与新 run 不重叠。OSC 不进入旧多视图 exporter/GPU 路径。publisher 打包完整 code、OSC predictor、纯缓存 helper、其导入的 MVKME 通用导出工具、`cvs_native_artifacts.py` 和冻结 BNNA 生产配置；无遗漏的新增运行依赖。入口在输出存在时拒绝，创建新目录并以 exclusive 模式写预测和日志，保持原缓存只读。未扩大对不变发布逻辑的审查。
