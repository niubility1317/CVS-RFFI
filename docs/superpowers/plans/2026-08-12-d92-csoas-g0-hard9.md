# D92 CSOAS G0与Hard9实施计划

## 冻结目标

先实现CSOAS科学路径并运行一个固定真实K10三场景truth-free G0。G0只判定机制、协议、D42非退化和资源；不读取性能。G0通过后才构建Hard9+K1同排性能实验。

## 实施顺序

1. Terra科学owner按TDD新增CSOAS核心，接入D92 probe、E0D slim/query及对应测试。
2. RED先锁定分类均值不变、加权中心scatter、逐类OAS、trace、组内label/row置换、K1/K2 alias、一次FULL fit、D42非退化和receipt篡改拒绝。
3. GREEN只实现冻结公式；不修改E0、D81、矩阵、阈值或历史方法。
4. 串行运行聚焦测试、E0/D92邻接回归、`py_compile`与diff检查。
5. 独立Terra复审科学正确性与真实入口，要求`P0=0,P1=0`。
6. 主代理提交本地Git，预注册不可覆盖G0 run ID、report、最小runtime closure和唯一K10 outer。
7. sole Luna runner执行N607唯一truth-free prediction命令；不读取truth、不运行scorer、不改方法、不重试同run。
8. 三场景均active、state非E0、codec量子门与资源硬门通过后，机械owner克隆Hard9+K1 runner/analyzer。
9. 独立复审机械闭包后提交并由sole runner完成8shard实验、完整取回，再由主代理分析八指标。
10. 任一八指标持平/反向或资源失败即拒绝；全部严格改善才进入Target125。

## Ownership

- 科学owner：`stage2_d92_cauchy_scatter_oas.py`、D92 probe、E0D slim/query及其测试。
- 机械owner：仅在G0通过后新增CSOAS Hard9 config、matrix、runner、analyzer、CLI及测试。
- 主代理：设计与追溯、diff整合、独立复审、Git/report、实验冻结和晋级裁决。
- sole runner：冻结交付落地、唯一launch、健康/资源证据、artifact取回；禁止调参、改方法或解释性能。

## 时间边界

设计已冻结，不再开第三候选。科学实现只做一个RED→GREEN回路；G0技术修复最多两轮。Hard9是唯一性能筛选，不进行强度、权重、rho、receiver、seed、K或new class count扫描。
