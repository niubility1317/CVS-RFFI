# PAMF Phase2 执行前容量核查

2026-10-28 直接读取 N607 既有 ManyTx 的容器计数，尚未生成目标信道或读取 query 真值。当前 7 个目标 RX、6 个旧 TX 与固定 20 个新 TX 的 182 个 RX/TX 组合，每个日期均为 50 条，4 个日期共 200 条。该事实不同于设计阶段所需的容量假设。

原总表为 8 个综合组与 3 个独立单场景组，要求物理 ID 互斥，每组 36 条 support 池与 30 条 query，即每 RX/TX 需要 726 条，现有文件不满足。即便每组仅保留 K=20 与 1 条 query，11 组也至少需要 231 条，仍超过 200 条。因此不能靠缩小 query 或减少 support 抽样次数保留全部原设置，更不能重复叠加同一物理记录后声称独立数据组。

已提出需要用户选择的数据调整。可行候选是保留 11 个互斥组，K=1/5/10，每组 support 池 10 条、query 8 条，共用 198 条，剩余 2 条。该候选合计 36,036 条独立物理记录，其中综合组 26,208 条、单场景组 9,828 条。它会改变原预算和结论适用的 K 范围；未经用户选择不启动。

采用该候选时，K=10 会使用全部 10 条 support 池，不同 support seed 仅改变排列，不能当作 5 份独立 support 集。MILKR 的完全相同终态应精确复用；统计不能把这些重复拟合视为独立试验。源模型种子、8 个综合组和较小 K 的抽样仍分别统计。上述候选尚未被选定。

另一条路线是保留 K=20 但缩减组数并明确诊断预算，或取得更多可核实物理记录后保留原设计。跨文件、跨表示或同记录多次信道实现均不能自动增加物理样本数量。

源域权重检查和无 query 接口验证不受该容量问题影响。独立登记 `20261028-phase2-pamf-dura-readiness-s2026092701-r01` 只排入一个 source-only 真实 checkpoint smoke；`preparation_only=True` 的队列中没有目标 builder、恢复、特征导出、预测或评分作业。当前还不能将其称为正式 Phase2 目标性能实验启动。
