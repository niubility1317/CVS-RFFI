## 方法与总体结果

P1 控制在每个其他 RX 中寻找同时不同 day 的最近邻，并要求对应 RX 反向也选回。PAIR 主规则还要求同条 P0/P1 在两个方向都选择相同邻居。候选只看单位特征和公共元数据，不看 y；FP64 cosine、opaque ID 字典序处理距离 ties。

仅在 L 上选择最大的可行距离阈值，距离 ties 整组纳入。全局、五个 RX、六个已知 TX 的 incident-edge 组各需精度≥98%、边数≥25；全部阈值冻结后才对 OE 挖掘并筛选。精度是该规则在 L 上的拟合结果，不能当作 OE 真精度。

| 规则 | L 候选边 | L 实际同设备边 | L 候选精度 | OE 无标签候选边 | 合法阈值 | 最终 OE 训练边 |
| --- | ---: | ---: | ---: | ---: | --- | ---: |
| P1 | 1674 | 1358 | 81.1231% | 2040 | 无 | 0 |
| PAIR | 25 | 22 | 88.0000% | 49 | 无 | 0 |

两规则的可行距离阈值数量均为 0，因此阈值保持 null，L/OE 最终直接边全部为空。OE 2040／49 是未经合法距离阈值筛选的无标签候选数，真实同设备精度未知；不是训练标签数或发现类数。

PAIR 全部候选仅 25 对。任何单一距离阈值都只能删除其中的边，不能补足每个 RX／TX 至少 25 对的要求；TX8-20 在候选中完全没有 incident edge。因此本轮失败包含明确的覆盖不足，不能仅解释成阈值不够合适。PAIR 的 L 总体 22／25=88% 也未达到 98%。

P1 虽有 1674 对候选，但仅 1358 对同设备；全距离层搜索也没有同时满足各组精度和最小边数的阈值。不能因为某些容易设备有高精度就把跨设备错误关系当作可靠的无标签身份监督。
