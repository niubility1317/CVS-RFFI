# SF-TAPFT V2容量矩阵全面实验报告

## 1.结论先行

本轮SF-TAPFT V2容量矩阵已完成16/16个run，16个run均生成`selection.json`和可加载的全support refit bundle，完整日志与selection逐字段一致，未发现Traceback、CUDA OOM、NaN/Inf或FAILED指纹。所有run均保持source、query、query truth、query role和target eval关闭，未修改非许可参数，未更新BN运行统计。就“实验是否正常完成”而言，结论为`VERIFIED`；就“是否已经证明真实Phase2 query性能提升”而言，结论仍为`UNKNOWN`。

当前最强的support-inner候选是`P3-R16-rho=1.0`：4折OOF平衡准确率从冻结CORE90的`60.4167%`提高到`90.9722%`，提升`30.5556pp`；NLL从`4.746183`降至`0.365321`。但该结果只来自receiver`20-1`、单一优化seed`392002`、旧类6类、每类K=10、共60条support的内部4折验证，且artifact明确标记`DIAGNOSTIC_NON_FORMAL`，不能替代独立query的truth-last评分。

本轮最重要的研发结论不是“越大越好”，而是已经出现明确的瘦身信号：

1. `P0→P1→P2-R16`的OOF平衡准确率依次为`85.4167%→86.1111%→89.5833%`，说明norm和rank16时间Adapter具有增量价值。
2. `P2-R16→P3-R16→P4-R16`的OOF结果完全相同，均为`89.5833%/0.410612 NLL`；但最终bundle中发生变化的元素数依次为`6,881→16,385→105,377`。P4相对P2扩大约`15.31倍`，没有产生可观测OOF收益。
3. `rho=1.0`比默认`rho=0.5`提高`1.3889pp`，且NLL更低，表明在这一support内部诊断中，纯目标原型初始化优于源头与目标原型各半混合；这是当前最值得进入独立query验证的机制。
4. `KD=0.1`把OOF平衡准确率从`89.5833%`降至`86.1111%`，虽然平均margin更高、参数距离更小，但分类正确性下降，不应作为当前主候选。
5. rank并非单调增益：P3的rank4、8、16、32分别为`87.5000%`、`82.6389%`、`89.5833%`、`87.5000%`，rank16最优，rank8反而最差。

因此，当前科学建议是：保留`P2-R16`作为最小高性能骨架，优先验证`rho=1.0`；P3/P4暂不晋级，除非独立query证明其最终refit bundle具有P2没有的泛化收益。

## 4.方法设计与实现

### 4.1模型初始化

输入CORE90 checkpoint被深拷贝为冻结teacher和待适应student。时间Adapter以残差形式挂到`meta_adapter_time`，上投影权重和偏置清零，因此插入瞬间保持恒等映射，不会在第一个梯度更新前改变checkpoint输出。

分类头采用归一化余弦头。旧类第`c`行初始化为：

`w_c=Normalize((1-rho)·w_source,c+rho·p_target,c)`

其中`w_source,c`是Phase1分类头的归一化权重，`p_target,c`是该类support embedding均值的归一化原型。`rho=0.5`表示源头和目标原型等权，`rho=1.0`表示完全采用目标support原型。分类logit为`8·cos(z,w_c)`。

分类头在适应过程中可训练并持久写入bundle。这正是artifact标记`DIAGNOSTIC_NON_FORMAL`的原因之一：本轮遵循当前对话中放宽后的高性能上界研发授权，但它不是“冻结原型边界”的轻量正式方案。

### 4.2训练目标

每一步的总损失为：

`L=L_CE+0.5·L_LOO-proto+1e-4·L_L2-SP+lambda_KD·L_selective-KD`

- `L_CE`：类别均衡交叉熵，label smoothing=`0.05`。
- `L_LOO-proto`：对当前样本计算其类别原型时排除该样本，避免样本用自身构造原型后产生平凡高相似度。
- `L_L2-SP`：对允许更新的norm、末段和fusion参数施加相对输入checkpoint的均方距离约束。
- `L_selective-KD`：仅在旧类范围内使用teacher软目标，并以teacher对真实类的置信度幂次作为可靠性权重；温度`2`、gamma=`2`。除M06外，`lambda_KD=0`。

优化器为AdamW，weight decay=`1e-4`，混合精度开启，梯度范数裁剪=`1.0`，全局warmup比例`0.05`，随后采用余弦衰减。

### 4.3P0-P4嵌套开放范围

分类头在所有profile和所有阶段均训练。下表只列student模型侧新增开放范围。

|profile|A阶段|B阶段|C阶段|设计目的|
|---|---|---|---|---|
|P0 head-only|无|无|无|验证只重估分类边界的上界|
|P1 head+norm|`time_fuse.1`及`t1/t2/t3.norm`|同A|同A|允许小规模统计/仿射校准|
|P2 time Adapter|同P1|P1+`meta_adapter_time`|P1+Adapter|最小可学习特征变换|

frequency和domain分支始终冻结。所有模型保持`eval()`，Dropout关闭，BN running mean/variance/count不更新。

### 4.4选择与最终refit

每个候选先执行4折support-inner训练。折内checkpoint按验证集的以下字典序选择：平衡准确率、类别floor、负NLL、macro-F1、平均margin、负参数距离；每个fold保留top3 checkpoint并在允许变化的delta空间平均。OOF汇总后，只有当非退化fold比例大于0.5，且NLL改善，同时平衡准确率或margin至少一项改善时，才选择`adapted`，否则回退到`zero_adapt`。

选择`adapted`后，A/B/C每阶段步数取4个fold最佳步数的下中位数，再用全部60条support执行一次固定最终步refit并导出bundle。最终refit不使用fold0模型，`fold0_as_final=false`。

必须注意：本报告中的OOF指标评估的是各fold的选择模型，不是最终全support refit bundle。最终bundle只完成了support-only refit和状态审计，没有再打开独立query。因此，P2/P3/P4 OOF相同不能证明它们导出的最终bundle在独立query上完全相同。

P2、P3、P4在rank16上的OOF结果完全相同，并不意味着C阶段没有执行。P3和P4的最终bundle审计显示末段/融合参数确实发生变化。完全相同的OOF值说明现有折内top3选择没有产生可区分的C阶段收益；一种与实现相符的解释是高分checkpoint主要来自较早阶段，但当前artifact没有记录top3的逐checkpoint阶段，不能把这一解释写成已证实原因。OOF评分落在折内选择模型上，而最终full-support refit又按阶段下中位步数另行训练，因此C阶段价值只能由最终bundle的独立query评分判定。

### 6.3rank：容量与性能不单调

在P3、rho=0.5下，rank4/8/16/32的BA为`87.5000%/82.6389%/89.5833%/87.5000%`。rank16最好；rank8的fold2只有`63.8889%`，使总体方差升至`0.016348`。rank32没有超过rank16，说明adapter瓶颈容量不是当前主要限制。

rank4只改变`12,533`个元素，BA比rank16低`2.0833pp`；它仍是有意义的进一步瘦身候选，但应在rank16通过独立query后再比较，避免在support-inner噪声上过早牺牲性能。

### 6.4KD：更接近teacher不等于更高准确率

加入`KD=0.1`后，模型参数距离从`0.002879`降到`0.002040`，平均margin从`2.795417`升到`3.580412`，但BA从`89.5833%`降到`86.1111%`，NLL从`0.410612`升到`0.442336`。这表明KD确实加强了teacher约束，却妨碍了目标receiver上的分类纠正。当前不建议保留KD；如果以后担心独立query遗忘，应以真实query旧类floor为依据重新决定，而不是用参数距离替代性能。

### 6.5C300/C500不是纯C阶段长度消融

M10和M11分别把计划阶段从`500/1500/2500`改为`500/1500/300`和`500/1500/500`。实现中的warmup和余弦衰减按总步数计算，因此总步数从4500变为2300/2500时，A/B阶段的实际学习率轨迹也随之改变。它们的最终A/B选择步数也从R0的`203/197`变为`152/199`和`157/200`。

因此，M10/M11只能解释为“缩短总调度”的联合消融，不能严格归因于“仅缩短C阶段”。两者BA均为`87.5000%`，低于R0的`89.5833%`，但该差异可能来自前两阶段的调度耦合。若后续需要纯C长度因果实验，应固定A/B的分段学习率时钟，不让C预算改变A/B schedule。

### 6.6折间稳定性与最困难fold

冻结模型四折BA为`61.1111%/69.4445%/44.4444%/66.6667%`，fold2显著最难。最佳M08对应为`100.0000%/91.6667%/77.7778%/94.4445%`，四折全部不退化，但fold2仍是最低点。rank8在fold2只有`63.8889%`，P0为`69.4445%`，KD和rho0.75/1.0均为`77.7778%`；P2/P3-R16达到`83.3333%`。这说明候选差异主要由困难fold中的少数样本决定。

以四个fold的配对BA差值作纯描述性t区间，M08平均提升`30.5556pp`，95%区间约为`[19.1430,41.9681]pp`。由于只有4个fold、验证集仅14或16条，且fold并非独立重复实验，该区间不能替代多seed或独立query置信区间。

### 6.7margin与NLL不能脱离分类头尺度解读

冻结模型平均margin为`5.402681`，高于所有适配候选，但冻结NLL高达`4.746183`且BA只有`60.4167%`。这并不矛盾：少数极高置信正确样本可以抬高平均margin，而错误样本的极低真实类概率会显著抬高NLL。适配还更换并训练了归一化原型头，所以margin绝对值不能单独用于冻结/适配间晋级。当前选择规则正确地要求NLL改善，并结合BA或margin改善，而不是只比较margin。

## 9.异常与局限

1. **没有独立query。**这是当前最大的科学限制。所有漂亮的BA/NLL数字都只能表述为support-inner诊断。
2. **单receiver、单seed。**没有跨receiver、跨scene、跨seed证据，不能说明稳定泛化。
3. **持久分类头。**该实现主动训练并导出新的归一化原型头，因此permission为`DIAGNOSTIC_NON_FORMAL`；它不满足此前“冻结分类边界”的轻量约束，但符合当前先建立高性能上界、再逐步瘦身的任务授权。
4. **最终refit未独立评分。**OOF选择与最终full-support bundle是两个不同对象，不能用前者替代后者的真实query性能。
5. **group粒度有限。**当前group来自每个validated support row；如果多行可能共享更高层物理采集源，现有分组无法识别该相关性。
6. **C300/C500调度耦合。**不是纯C阶段消融。
7. **缺少资源遥测。**没有可信wall-clock、吞吐和峰值显存，因此本轮只能比较状态变化规模，不能给出性能/成本Pareto的完整系统结论。
8. **方法标签与实验标签不同。**artifact内`method=sf_tapft_v1`，实验和runner称为V2；V2指本轮新增的全support refit、P0-P4profile和容量矩阵，不应误写为底层方法schema已经改名。

启动过程中曾有一个R0解释器路径错误run，在进入Python前退出，未读取数据、未占用GPU、未生成性能产物；正式R0使用正确解释器重新启动并完成。矩阵初版launch脚本也曾在预检阶段因变量转义问题退出，经回读确认没有创建正式run或日志后才修复发布，没有重复启动正式run。这些属于发布技术异常，不是性能结果。

## 10.研发决策与下一阶段

### 10.1当前晋级顺序

1. **首选高性能候选：**`P3-R16-rho=1.0`。理由是support-inner BA和NLL均为全矩阵最佳。
2. **首选瘦身候选：**`P2-R16-rho=1.0`。本轮没有直接运行这一组合，但P2-R16与P3-R16在rho=0.5下OOF完全一致，而rho效应主要来自分类头初始化；该组合是最合理的下一张最小验证卡。
3. **进一步瘦身候选：**`P2-R4-rho=1.0`，仅在P2-R16独立query通过后再测。
4. **暂缓：**P4、rank32、KD0.1。当前没有足够收益支持其复杂度。

### 10.2最小下一实验

下一步应保持同一checkpoint、capsule、split、K=10和60条support不变，直接对最终bundle运行独立query prediction，再由独立scorer连接truth。最小同row比较至少包含：

- `DA0_REG0`：冻结CORE90；
- `DA1_REG0`：P3-R16-rho1.0；
- `DA1_REG0`：P2-R16-rho1.0；
- 可选资源对照：P2-R16-rho0.5。

报告旧类准确率、旧类floor、NLL、延迟、显存和最终bundle大小；REG0的新类准确率与old/new harmonic必须记为`N/A`。只有独立query显示稳定正收益且旧类floor不过度下降，才进入多seed或ERBT-IDR叠加实验。

### 10.3尚未覆盖的设计实验

本轮矩阵覆盖了R1中的P0-P4、rank、KD、rho和缩短总调度，但没有覆盖设计报告中的全部后续实验。以下仍为`DEFERRED`，不是本轮已经完成的结果：

- R2/R3跨receiver、跨scene或多seed确认；
- S0、S3、S5等后续瘦身/结构消融；
- 独立query truth-last性能闭合；
- 最终bundle的wall-clock、吞吐和峰值显存profiling；
- 与ERBT-IDR的同row叠加效果。

## 11.设计追溯总结

- 已验证：5个嵌套profile、4个rank点、3个rho点、KD开关、2个短总调度、16个正式run、16个bundle、64个fold row、统一协议绑定、full-support refit、无query/source状态审计。
- 延后：独立query、多seed、跨receiver/scene、后续S系列瘦身、ERBT-IDR叠加、完整资源profiling。
- 近似实现：当前group只能使用validated support row物理ID；V2沿用`sf_tapft_v1`底层method标签；C300/C500是总调度联合变化。
- 阻断项：无技术阻断；科学晋级被“缺少独立query评分”阻断。
- 最高风险偏差：如果把support-inner OOF直接当成最终域适应性能，就会高估方法；如果把P2/P3/P4相同OOF直接当成最终bundle等价，就会忽略full-support refit后的状态差异。

## 12.最终判定

本轮已经证明：在固定receiver`20-1`的60条旧类support内部，SF-TAPFT通过重估分类头、norm和时间Adapter可以显著改善OOF分类；纯目标原型初始化`rho=1.0`给出最强support-inner信号。矩阵同时证明，高容量P3/P4没有带来可观测OOF增益，P2-R16是当前最有价值的瘦身骨架。

本轮尚未证明：这些最终refit checkpoint在独立Phase2 query上优于冻结CORE90，也未证明跨receiver、跨scene、跨seed稳定，更未证明与ERBT-IDR叠加有效。因此最终科学结论为：`SUPPORT_INNER_POSITIVE / INDEPENDENT_QUERY_UNKNOWN / NO_PROMOTION_YET`。
