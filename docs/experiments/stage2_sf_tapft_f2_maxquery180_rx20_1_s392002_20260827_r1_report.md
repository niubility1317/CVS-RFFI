# SF-TAPFT F2最大Query 180条适应前后对比报告

## 1.结论

现有receiver=`20-1`、`leo_clear_weak`固定received-IQ母资产对旧6类每类提供40条独立物理观测：20条support pool和20条独立Query。固定K=10后，每类可用于Query的最大数量是30条，即support pool未使用的rank10–19共10条，加独立Query分区20条；6类合计180条。

F2域适应在这180条最大并集上把正确数从130提高到151，BA从72.2222%提高到83.8889%，提升11.6667pp；最低类别准确率从10.0000%提高到53.3333%，提升43.3333pp；NLL从0.870038降到0.510796。26条Query由错转对，5条由对转错，双侧精确McNemar检验`p=0.000192`。因此，`DA1_REG0-DA0_REG0`在最大可用Query并集上仍是明确正收益。

结论不是“所有类别都改善”。类4从96.6667%下降到83.3333%，回退13.3333pp；类1下降3.3333pp。主要收益来自类0（+30.0000pp）和困难类3（+43.3333pp）。F2可以保留为快速域适应工作点，但这组单receiver、单scene、单seed结果仍不足以把它提升为默认最优方法。

## 2.最大Query口径

|分区|物理来源|每类数量|总数|状态|
|---|---|---:|---:|---|
|K10 support|support pool rank0–9|10|60|只用于适配，不进入Query|
|Q60|support pool rank10–19|10|60|上一轮已形成不可变F2预测并truth-last评分|
|Q120|独立Query分区|20|120|本轮形成不可变F2预测并truth-last评分|
|最大Query并集|Q60∪Q120|30|180|opaque Query ID交集为0|

Q60与Q120不是同一批样本的重复view。母资产在一次性builder阶段把support pool与独立Query绑定到不同物理样本；本轮又直接核对两组opaque Query ID交集为0。并集只连接两组既有逐样本预测，不执行类别配额、全局重排、重新适配或query反馈。

Q120单独是“最大独立Query分区”；Q180才是“固定K10后，现有全部固定received-IQ的最大Query上界”。不把K10 support计入Query，也不复制样本或生成第二个LEO观测。

## 3.方法与实现

F2为`S15-SCHED300+OOF全局温度`：完整cosine日程300步、warmup 30步，研究选择步为`[150,0,0]`；训练`head+all time norm`且不训练Adapter，可训练/实际变化元素均为1584。推理温度为`T=1.071440445141165`。本实验不注册新类，只比较：

- `DA0_REG0`：同一基础checkpoint和K10 support构建的适应前状态；
- `DA1_REG0`：同一F2 clean-single bundle的适应后状态。

实现提交`0f3152b4e4b3c1f098fc9c51199dba02140c657c`增加三项能力：闭合器按`data_handle.query_rows`处理可变Query数量；从既有预测包导出完整无标签独立Query；只有DA0/DA1两份prediction的ID、预测向量、6类score矩阵和有限性全部闭合后，才允许连接独立truth sidecar。31项聚焦测试、远端编译和真实checkpoint无Query smoke通过。独立P0/P1审查发现并修复“损坏score仍可能提前连接truth”的P1，定点复审无残留P0/P1。

预登记报告最初把F2阶段写成`100/100/0`。严格smoke从真实bundle回读后确认实际研究选择步为`[150,0,0]`；这是一处报告元数据错误。真实bundle、命令、模型状态和prediction均绑定实际F2配置，没有按错误文本运行。

## 11.最终判断

F2域适应在最大180条Query上有效，结论记为`POSITIVE_DA_ON_MAX_AVAILABLE_QUERY`。它同时改善BA、floor、NLL和ECE，并通过同row配对检验；这个结论比60条Query更稳定。

仍不晋级为默认最优checkpoint。原因不是域适应无效，而是三点边界：类4有13.3333pp回退；类3适应后仍只有53.3333%；当前证据只覆盖receiver=`20-1`、`leo_clear_weak`、单seed。下一步若继续优化，应优先研究类置换不变的局部边界保护或支持集不确定度加权，并用新的receiver/scene/seed确认，不能用本次已揭示Query重新拟合温度或选择步数。
