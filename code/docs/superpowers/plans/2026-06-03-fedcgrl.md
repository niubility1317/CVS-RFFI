# FedCGRL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a federated calibrated GRL controller that adapts receiver-adversarial strength per client and logs enough diagnostics for N607 validation.

**Architecture:** The controller lives in `code/federated/fed_grl_controller.py` and computes per-client `lambda_rx_adv` multipliers from round progress, receiver leakage, TX preservation, and gradient-conflict diagnostics. `FederatedTrainer` owns one controller, passes the per-client lambda into local loss assembly, updates the controller after each round, and writes controller state into config, logs, metrics, and stdout. CLI flags in `code/train.py` keep the feature opt-in and preserve existing fixed-GRL behavior by default.

**Tech Stack:** Python, PyTorch tensors, `unittest`/pytest, current CVS-RFFI federated trainer.
