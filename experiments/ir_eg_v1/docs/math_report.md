## Interfaces

`ir_types.py` defines the exact frozen dataclasses in `math_brief.md`. `build_layout(model, optimizer)` deduplicates parameters by identity. `names` and `shapes` follow optimizer group order; `phi_indices` follows the complete native `adv_head.parameters()` order, so grouping/reordering cannot change head tensor semantics. The public alias `build_param_layout` is also available. Frozen parameters remain represented in phi or psi; all optimizer slots belong to exactly one block. In particular, frozen head tensors remain part of the numerical four-tensor forward function. Activity is separate: a frozen tensor has `h0=None`, no metric coordinates, no response increment, and no formal gradient. A head tensor omitted from the optimizer raises an explicit unsupported-layout error.

`audit_contract(model, optimizer, ctx)` requires an actual `native_loss` tensor, named `task_terms` tensors, a `head_batch`, and `expected_code_root` independently supplied by the launcher. It rejects task gradients into trainable phi and compares actual weighted native head gradients against deterministic replay projected onto trainable coordinates. It retains caller graphs. Reports contain exact sample IDs, sample weights, effective coefficients, GRL multipliers, task names, and pinned import paths/hashes. The mandatory provenance check uses the independent expected root, checks loaded math helpers and any loaded critical native modules, and cannot be bypassed by omitting optional expected imports. Integration must supply the complete native task ledger; the helper cannot infer whether a caller deliberately omitted an unreported task.

`audit_runtime_imports(expected_code_root)` is the formal entrypoint helper. After native imports, it requires `model_dual_cvsincnet`, `cvsrffi.game_tracking.solvers`, `cvsrffi.game_tracking.state`, `cvsrffi.game_tracking.legacy.objective`, `cvsrffi.xuc_fusion.objective`, `cvsrffi.xuc_fusion.dr_objective`, `cvsrffi.xuc_fusion.joint_normalization`, and `SSDG.train_ssdg` to be loaded from the expected execution-package code directory. It additionally checks loaded model/model_modified/legacy-model and IR modules. Math-only contract tests do not need to load this native stack.

`capture_head_calls(head, layout_signature, context_signature)` is a context manager. It yields a tape with `records`: each record contains `post_grl_input`, `logits`, `scaled_dropout_mask`, and pre-Dropout `dropout_rng`. The original post-GRL tensor/logits identities are retained for packet assembly. Only `tape.register(key, physical_ids, domain, sample_weight, grl_multiplier, call_index=...)` registers domain supervision. The default index is the latest call. Extra LEO forwards stay outside `tape.batch()`. Hooks are removed in `finally`, including exception paths. This requires no default model-forward edits.

`head_logits(phi, call)`, `head_loss(phi, batch)`, `head_gradient(phi, batch)`, and `ggn_matvec(phi, batch, vector)` expect four tensors in native Linear/ReLU/Dropout/Linear parameter order. The derivative functions use detached head features and fixed masks. The head math supports FP64 oracle tests; production metric inputs and optimizer moments are restricted to FP32. `head_logits` alone permits the packet's post-GRL tensor substitution so final first-order encoder gradients survive.

`build_response_metric(origin_optimizer_state_dict, predictor_record, h0, layout)` accepts `predictor_record = {'clip_coefficient': actual_c, 'optimizer_after': virtual_state_dict}`. Optional `optimizer_class` is checked when present; passing a live optimizer instead of a state dictionary enforces exact AdamW type. Serialized AdamW identity must also be enforced by the owning solver because a bare PyTorch state dictionary contains no optimizer class. `h0` is the tuple in `phi_indices` order and preserves `None`. The returned vectors include only active response coordinates, indexed into the full flattened phi tuple. Real virtual second moments and per-parameter steps are checked before building R. Zero learning rate, absent gradients, and zero clipping exclude response coordinates. Weight decay is kept out of GGN.

`solve_response(e, metric, ggn_operator, max_iterations=2, rtol=1e-3)` takes full phi vectors at the GGN boundary and returns whitened active-coordinate u. The integration must multiply by `sqrt_diagonal` once and scatter through `active_indices`. Nonfinite values or a nonpositive search denominator return `numerical_failure`; reaching the iteration cap returns `truncated_usable`, not a fallback. Shape/layout changes raise structural errors.
