# 物理融合预测的共享计算与交接

当前结论：不接管正在运行的三个原预测。2026-11-03 在 N607、CPU 每进程两线程、batch 8 的 104 条源记录上，三个原进程同时运行耗时 10.0919 秒，共享进程耗时 10.7059 秒；共享方案在这次测量中慢约 6.1%。样本有限、测量顺序固定，不能据此预测所有负载，但也不支持立即切换以缩短完成时间。单进程依次运行三个模型的 2.85 倍比值不能作为当前并行任务的加速比。

## 可共享范围

对输入、门控、DURA、物理后验、分类器和数值设置完全一致的三个物理融合模型，共享同批门控、DURA、物理后验以及 raw／DURA 分类；各候选网络和恢复输出分类保持各自原顺序。其他模型不能仅因名称含 DURA 就假定满足复用条件。源样本上每条波形、门控和类别逐项一致不等于目标全集已经一致。

## 当前全量复核

`full_replay.py` 首先运行真实 checkpoint 的无目标源域检查，然后等待三个原任务的七景完成标记。仅在原输出完全固定且 CPU 负载符合条件后，程序以只读方式重放原输入，逐条比对每个模型的 raw 和 restored 分类，以及各景门控总数。诊断不访问测试真值、不会改写原任务，也不用于模型选择。原任务没有保存全部恢复波形或逐条门控，因而不能宣称已对这些量做了全量逐值对比。

## 未来交接的最低条件

1. 先核对同一输入和物理 ID 顺序、七景、冻结模型及识别器、batch、精度与原运行一致；发现不匹配时不得复用中间值。
2. 先验证完整输出的逐条分类和已保存的门控统计一致，再在接近实际负载下比较三个原进程并行与共享方案的端到端墙钟时间。实测未缩短时不接管。
3. 只在可以证明完整写入并固定的场景边界交接；运行中或未完成的 memmap 不当作已完成产物。原文件、日志、已完成预测和评分结果均保留。
4. 交接须有唯一预测 owner，避免重叠写入；在隔离输出中准备候选并核对自动评分器与完成标记的关联，确保评分仍仅在七景预测全部固定后进行。不得覆盖原任务，也不得让两个 owner 同时写同一结果。

当前代码提供共享计算和只读全量复核，不提供可直接替换正在运行预测进程的交接控制器；上述条件不是已完成的切换声明。
