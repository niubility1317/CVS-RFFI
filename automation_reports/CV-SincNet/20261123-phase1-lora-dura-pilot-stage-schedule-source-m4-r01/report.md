# LoRa DURA 单次端到端训练的阶段调度对照

## 实验设计

对比恒等观测、接收前导均衡两种结构中，恒定联合损失与粗恢复优先调度的效果。每个候选从相同固定种子初始化，在一个进程里运行 1,400 步。粗恢复、观测约束和细化模块始终参与前向和反向传播。全程使用同一个 AdamW 优化器和学习率日程。各阶段沿用优化器状态与网络权重。

前 280 步采用粗恢复、细化恢复、双观测一致性权重 0.80、0.20、0.02。第 280 至 700 步线性过渡到 0.35、0.65、0.10，随后保持到 1,400 步，与恒定对照的目标一致。沿用对照的网络、数据、批次、通用扰动、训练预算和读出。恒定对照复用已冻结的同包源域测试，配对统计按接收机分层抽样。观测算子由当前实收 IQ 和已知协议前导决定。训练和冻结只读取合法源 U clean。拟合过程不读 TX 标签、冻结 F、源 V、目标或任何 practical 仿真参数。

## 验证与运行

入口为 `python -m experiments.pamf_lora_main.pilot_joint_source publish --staged`，使用 N607 普通账户、既有 LoRa Python、独立 release CWD 与不可覆盖的 `20261123-phase1-lora-dura-pilot-stage-schedule-source-m4-r01` 输出根。调度采用发布时实际可用的两张不同 GPU，计入全机其他任务占用，每卡总计算进程限制为四。支持 BF16 时，训练的卷积使用 BF16，复数求解、FFT 和正式评分使用 FP32。训练后按固定源校准阈值冻结，full 和 residual 分卡在五台源 RX 的 900 个共同包上做 clean 和六景预测，再独立使用真值。按各训练对照报告耗时、六景均值、低城区、净纠错及 clean。任一 smoke 或冻结契约失败、非有限值或评分缺项时停止本 run 的后续派发，保留现有产物。
