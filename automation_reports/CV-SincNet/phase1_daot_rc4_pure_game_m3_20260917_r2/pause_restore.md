# 释放GPU前的恢复验证

用户授权：腾出GPU给其他任务，先补齐并验证可恢复断点。唯一执行owner为本任务/root。

## 范围和状态

本次仅处理phase1_daot_rc4_pure_game_m3_20260917_r2所属进程。纯博弈18行支持同row、同物理数据角色、同seed和同训练预算的epoch断点续训；恢复写入新输出目录，保留原产物。恢复不加载query，不用目标成绩选模或选择重跑。历史父链为本run从零初始化，不继承其他数据契约权重。

原生DAOT＋RC4三行rc4_recovery_checkpoint_interval=0，正在运行的入口没有保存信号或控制文件接口，磁盘修改不能安装到旧进程。不得声称其已有可恢复中间点，不终止这三行；保持运行至E200自然释放。新支持代码只覆盖纯博弈，本报告不声称原生恢复已经实现。

## 恢复实现

恢复模型、EMA、AdamW状态、原型、求解器、ticket采样进度和DR载体状态。严格检查row、配置、source_info完整角色、从零父链、target_contact=false、epoch与接受步及各组件提交计数。新断点增加全局RNG、计数器、耗时和恢复父链；新入口支持在完整epoch边界收到请求后保存并退出。

旧r2纯博弈断点没有外层RNG，但每个随机训练更新在isolated_rng(ticket.seed)内执行，使用已保存的固定ticket。只允许显式--allow-legacy-ticket-resume进入这一已审计路径；其他缺少状态的路径拒绝。正式CUDA原有非确定性内核保持不变，因此恢复完整状态不等于承诺后续逐比特轨迹相同。验证用确定性内核隔离序列化影响，正式参数不改变。

## 停止顺序

1. 对原子替换写入的latest_ssdg.pth建立不可覆盖硬链接快照，保留原文件与日志。
2. 六方法真实训练步骤断点恢复测试通过，再逐一将远端快照在CPU重建，检查模型、EMA、优化器、原型、求解器、ticket及载体状态。
3. 仅在全部当前pure worker的快照验证通过后，冻结本run调度器并核对实际/proc进程，避免新行启动竞争；结束调度器，排队行登记HELD_USER_PAUSE。
4. 仅终止身份匹配且已验证断点的pure worker，独立读回进程与GPU状态。按实际停止步与快照步报告需要重算的步数，不能把快照之后的进度记为已恢复。
5. 原生三行继续运行。后续恢复由新的唯一owner按本清单、新输出目录和显式恢复命令接管，禁止重启旧dispatcher或从零误跑已训练行。
