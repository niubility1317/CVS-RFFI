# 源端零干预与物理干预诊断

本诊断服务于持续的三 seed clean ≥84% 目标，当前只定位源训练目标的混杂。上一轮完整源日志显示辅助步 margin-drop 梯度明显高于 CE；代码核查发现 clean/aux 使用不同 Dropout 掩码，parent 缓存为 eval 而学生为 train。需要先量化无物理变化时的假阳性约束，不能把所有 margin 差值归为通信扰动。

固定使用对应三份原 E200 纯 CE 父权重、已完成来源核验的 L_s 缓存和 L/T 网络，每 seed 覆盖全部 6300 个有标签源样本。比较同 IQ 独立 train 掩码、同 IQ 确定前向、真实 L/T 确定前向，核查 keep、drop、CE、梯度范数与夹角。12 个预定批次用于梯度探针，不冒称全部批次梯度分布。参数、buffer、模式、grad 与 RNG 完整恢复，无优化器、无身份训练、无目标预测或评分。

结果用于决定下一版源域机制设计，仍从原父模型独立开始第二阶段；不继承测试较优变体。未来正式训练继续遵循每方案40轮、三seed、每卡最多4进程、冻结后自动clean测试。诊断本身不能证明84%性能目标完成。
