# clean 候选实验的结论与机制边界

本批 9 行全部完成，三个设置各三种子，固定 final20、逐行 clean 预测及独立 truth-last 评分。预登记主方案 DELAYCAP_JOINT 的均值为 79.9196%，未达到 84%。CAP_JOINT 为 80.0508%，与原 E20 基线 80.0504% 基本持平。完整每种子、分层和成本见 [final_analysis.md](final_analysis.md)。

与上一批同设置比较，加入 clean 候选的三种子配对均值差依次为：DELAY −0.0956 个百分点、CAP +0.1528 个百分点、DELAYCAP −0.0143 个百分点。方向不一致，三种子的波动及跨 run 数值轨迹差异均保留，不能据此声称该改动具有稳定泛化收益。固定对照见 [reference_comparisons.md](reference_comparisons.md)。这些结果不用于改变在训方案、筛选种子或安排选择性重跑。

## 实际改变了什么

源日志全部 39,960 步已核验。每行 3,996 次候选搜索中，clean 被选中 1,447 至 1,789 次，约占 36.2% 至 44.8%。其余步骤重放选中的风格候选。该比例表明 clean 分支实质性改变了训练，同时也说明风格分支没有完全退化为恒等变换。逐行次数见 [source_trajectory.md](source_trajectory.md)。

候选选择的定义是 `max(CE_clean, CE_style1, ..., CE_style4)`。所以选中候选的 eval CE 不低于 clean，本身是算法约束，不能作为新信息增加或泛化改善的证据。该改动仍沿用原来的四个凸插值候选，没有扩展特征统计的扰动范围。

按 `objective.py` 和 `style.py` 的实现，clean 选择时不安装风格 hook，并重放同一输入、训练模式和 Dropout 状态。在相同模型状态的数值等价条件下，额外 `style_ce` 就是再次计算原身份 CE；相应身份 CE 项约为 `(1 + style_ce_weight × ramp) × CE`。U 的 KL 和 Fishr 项仍存在。因此，这些步骤主要改变身份 CE 的相对权重，没有引入新的样本变化。CAP 设置下，联合限幅所使用的身份目标梯度也随之改变，不能把所有差异都解释为风格扰动更强。

## 后续在训验证的解释范围

受限双向统计扰动的 18 行矩阵已在本批完整结果出现前，依据源域候选范围和反事实诊断固定并启动。它检验正向／反向候选范围的差异；三个校准设置及三个种子全部保留。当前不调整其配置或预算，待固定 final20 与 clean 测试闭合后报告完整结果。

源候选变难、辅助损失能回传、特征变化增大，都只证明机制执行或源目标变化，不能代替 84% 的测试验收。双向变换仍是受限特征统计假设，尚不能等同于经真实 IQ 核验的物理信道变化。本批完成不意味着整个性能目标完成。
