# Orthogonal bridge: scoring and support-only findings

The clean hybrid pilot scored 30 K5/N20 results, five each for six DA backbones. All 30 have zero old-class macro accuracy. In the DADDA P01/MIX01/RX1-1 example, all 10,332 old query records were assigned to new classes; restricting predictions to the six old outputs yielded 94.89% old-class macro accuracy. These target outcomes have been exposed and do not constitute a blind test for subsequent changes.

The bridge freezes normalized affine classifier weights as old cosine weights, whereas new weights originate from B-encoder feature prototypes. This discards the old affine bias and scale. The objective updates new weights but leaves old weights fixed. In six support-only diagnostics, using independently saved B states from matching capsule and seed, all 30 old support examples selected a new class both before and after 50 registration updates. These are not the pilot's exact B states: the pilot did not save them. CPU and GPU kernels also differ.

An explicitly named project transplant, `support_prototypes_v1`, initializes old cosine weights from the already available old-support feature prototypes, while retaining the same B encoder and original Orthogonal registration objective. It does not preserve the original B affine decision at C entry and is not the author's native model. On the same support-only diagnostics, post-registration old support correct counts were 25/30, 26/30, 28/30, 27/30, 16/30 and 29/30 for DADDA, MRIOR, Poster, ProtoNet, Tweak and TwoStage, respectively. Original counts were 0/30 for all six. This does not measure new-class accuracy or query generalization and is insufficient to claim a complete repair. The candidate is opt-in and has not been wired into a formal experiment, predictions or scoring; the original results remain unchanged.

Native Orthogonal is a separate source-trained method, not this transplanted bridge. Its already-scored clean results also contain low old-class accuracy in multiple K/N settings, but no bridge diagnosis should be generalized to its separate architecture without further evidence.
