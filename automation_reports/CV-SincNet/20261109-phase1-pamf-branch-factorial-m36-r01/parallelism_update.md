# 调整并发上限

用户在首批训练启动后要求提高并发：GPU 0 至 6 每卡最多 3 个本实验计算进程，GPU 7 最多 2 个本实验进程。其他用户的进程不计入上述数量；每次派发仍要求实际剩余显存不少于 12,000 MiB，并沿用 CPU、内存和 IO 条件。已派发、尚未进入 GPU 的本实验进程计入上限。

此调整只替换本实验的调度控制器。原训练和预测进程保留原 PID、工作目录、代码版本、配置及输出；已完成模型不重跑。新控制器核验旧控制器身份后接管与登记配置完全匹配的健康子进程，并继续原有冻结预测与独立评分队列。科学结构、训练预算、数据权限和统计口径保持原登记。

2026-11-09 发布后独立核验：新控制器执行提交 `ccad75100e30500c9791e8b5912232e2a7abf19a`；原 14 个训练进程均以原身份接管。观察到本实验共 23 个训练进程，GPU 0 至 6 各 3 个，GPU 7 为 2 个；接管前后日志继续增长，未发现未解决故障。实际模型代码仍使用原提交 `17ac02d73c97386a160b1b6e80cb43c5a33fdd7d`。以上是发布快照，当前数量随任务完成而变化。
