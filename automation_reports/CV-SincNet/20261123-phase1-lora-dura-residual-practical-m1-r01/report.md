# LoRa DURA 在 residual practical 下重训

## 观测与数据

沿用 LoRa 原有 5 台源接收机、2,800 个 L 包、25,200 个 U 包和 15 台未见目标接收机的 30,000 个物理包。保留六个原有前导 chirp 和 clean 处理。Residual 引擎支持最多 1 ms 的冻结快照，本试验把带真实邻接上下文的 1 MHz 原始前导抗混叠重采样，再在每个已登记的 256 kHz、256 点 chirp 上运行一次 residual practical。每包六个快照共享同一个几何抽样、同一接收机硬件会话，各 chirp 的残差实现独立。使用 post-sync、无 EQ、868.1 MHz，参考 SNR 为 30 dB。以快照提前 8 个低速率采样点的真实上下文补偿已登记因果滤波数值延迟。所有 chirp 输出统一按包 RMS 定标。本方案与 full practical 的 1 MHz 连续波形路径存在处理顺序和快照相关性的差异，两者分开记录。

## 训练和正式验证

种子固定为 2026092702。源 L/U 每个物理包两套确定的 residual 观测，保持同包 clean 配对。作用训练使用同一观测的无噪波形拟合局部复增益，另由同轨迹的新增噪声计算方差。局部复增益是对角近似。源训练使用 15% clean 恒等曝光、配对观测相位对齐和去载波形状损失。粗恢复从零初始化，后续各阶段仅继承本轮直接父权重。保持原 DURA 八阶段、R65 延迟剪枝、R69 两阶段四步 CG 及 266,951 参数。各阶段 20 轮、4,940 步，共 39,520 步。恢复训练 worker 未收到目标或 F 权重路径，也不读 TX 真值或 V 标签。

G 权重冻结后才生成 residual 盲测视图，再接同种子冻结 LoRa Tri-set。固定比较直通、R69 原生波形、保留观测载波的全量限幅及半量。每个读出覆盖 clean 和六种 practical，15 台接收机共 420 份预测数组。独立评分程序验证全矩阵冻结后才读取目标真值，逐景和逐接收机记录纠对、改错、clean 变化和六景均值。另读已有同种子的 full practical 直通以及复响应半量作为跨路线比较。当前门控不跨路线继承。

## 发布和判定

在 N607 普通账户的独立运行目录 `CV-SincNet/runs/20261123-phase1-lora-dura-residual-practical-m1-r01` 执行。使用现有 LoRa 普通账户 Python 和冻结依赖，工作目录是同名 release。用 `python -m experiments.pamf_lora_main.residual_dura publish` 传入 repo、输出目录、普通账户运行环境、SSH 配置、现有物理数据和 Tri-set 发布回执。GPU 优先序为 3、0、1、4、5、6、2，源训练和预测各自最多一张卡。源配对或盲视图生成用 16 个 CPU 工作者。源真实数据 smoke 核对对齐、快照重放、无噪成分重构以及粗恢复、作用和 R17 梯度。运行中遇到输入、观测、非有限、checkpoint 或矩阵错误时停止本 run 并保留产物。

独立评分入口为 `python -m experiments.pamf_lora_main.residual_dura_score`，输入为新发布回执、SSH 配置、原数据集、独立输出根及已有复响应三种子结果。训练日志位于 `G/lineage/<stage>/training.jsonl`，盲预测位于 `predictions/`，正式读出为 `scores.json`。本次先完成单种子重训验证，三种子总体性能另外计入。

## 两路线源波形核对

从同源 L/U 抽查 30 个训练物理包。对两套快照分别重放，实际写入的 clean、received、局部动作系数和方差逐值一致。另从五台源接收机等量固定 240 个 V 包，比较完整六景。重放的 full IQ 与历史缓存逐值一致，residual 观测由该路线的信号与新增噪声重构。诊断不读 F、TX 真值或目标，也不参与正在运行的训练。

每条 chirp 用模拟器实际加的噪声计算信噪比。表中分别先计算同包六条的信噪比中位数和最大最小之差，再取 240 包的中位数。两项单位均为 dB。

| 场景 | Full 包内中位信噪比 | Residual 包内中位信噪比 | Full 包内跨度 | Residual 包内跨度 |
| --- | ---: | ---: | ---: | ---: |
| 高强度郊区 | 36.15 | 29.94 | 0.84 | 3.70 |
| 中强度郊区 | 31.83 | 25.89 | 0.86 | 9.10 |
| 低强度郊区 | 28.70 | 22.78 | 0.83 | 12.08 |
| 高强度城区 | 36.05 | 29.93 | 0.85 | 7.91 |
| 中强度城区 | 28.60 | 21.41 | 0.90 | 26.14 |
| 低强度城区 | 12.39 | 7.76 | 0.90 | 25.71 |

Residual 当前路线在六景的中位数均低于 full，弱城区内的样本差异也明显更大。低强度城区在扣除单一复增益后，无噪波形差的归一化中位数从 0.06574 变为 0.09808。用同一配对无噪轨迹拟合 17 点局部复增益后，residual 的误差中位数为信号功率的 0.0000534，误差功率与新增噪声功率之比的中位数为 0.000607。后两项衡量训练用的物理配对目标是否足够贴合样本，实际恢复器仍要从带噪观测估计作用。当前六景幅度和同包独立抽样均有实测改变。正式报告需优先比较同 residual 直通下 DURA 的净增益。

### 注入带宽和同包信道状态分解

在相同的 240 个固定源包上，用 128 次合成宽带复白噪声测量原 LoRa 抗混叠裁窗与重采样的功率传递率。平均保留 24.60%，对应 6.09 dB。Full 在 1 MHz 注入噪声后才通过滤波。Residual 在 256 kHz 注入噪声，输出没有再经过这次滤波。第一组反事实仅按上述功率系数缩放 residual 已采样的噪声，保留原作用轨迹和接收机锁定状态。前四景的中位信噪比因此接近 full，两者相差均不到 0.2 dB。中、低强度城区仍有约 1.1 和 1.5 dB 差距。

第二组源反事实让同包六条 residual 快照从相同非噪声状态开始，各条仍使用其原来的独立噪声抽样。它只用于诊断独立衰落与相位轨迹的影响。低强度城区如下。相干度由噪声观测与同包 clean 的归一化复内积计算。

| 路线或源反事实 | 包内中位信噪比 / dB | 包内跨度 / dB | 与 clean 相干度 |
| --- | ---: | ---: | ---: |
| Full 连续观测 | 12.39 | 0.90 | 0.819 |
| 已登记 residual | 7.76 | 25.71 | 0.664 |
| Residual，匹配噪声注入带宽 | 13.85 | 25.71 | 0.797 |
| Residual，同包共用非噪声状态 | 12.11 | 0.80 | 0.797 |
| 共用非噪声状态，另匹配噪声注入带宽 | 18.21 | 0.80 | 0.861 |

按带宽配平只改变噪声功率，包内跨度基本不动。同包共用非噪声状态使低强度城区的跨度由 25.71 dB 降至 0.80 dB，同时改变了中位信噪比。两项同时改动使低强度城区信噪比超过 full，表明两项效应在重衰落场景不能简单按固定 dB 合并。以上未读取识别器、TX 标签或目标。两种反事实均未替换正在训练的正式 residual 数据。

### 只用接收 IQ 定位弱 chirp

另取五台源接收机各 120 包，共 600 个源 V 包。每景用已登记 residual 数据，重放后确认信号与噪声逐条重构接收 IQ。以实际新增噪声轨迹计算每条 chirp 的信噪比，在每包内验证从接收 IQ 可获得的排序。下表为低强度城区。两两排序准确率使用包内 15 对 chirp。最差两条召回率计算估计前两条与真实前两条的交集。

| 指标 | 两两排序准确率 | 最差一条命中率 | 最差两条召回率 |
| --- | ---: | ---: | ---: |
| 接收功率 | 51.21% | 21.17% | 36.92% |
| 去啁啾相干度 | 98.47% | 97.00% | 98.25% |
| 90–105 kHz 带外比值 | 92.86% | 79.00% | 88.08% |
| 80–118 kHz 带外比值 | 95.43% | 86.33% | 93.08% |
| 窄带外比值乘相干度 | 95.02% | 90.17% | 92.75% |

接收功率受逐 chirp AGC 影响，在低城区排序接近随机。去啁啾相干度能可靠定位弱 chirp，六景两两排序正确率为 83.19% 至 98.47%。对低强度城区，用窄带外比值选出两条最差和两条最清晰的 chirp。在接收载波坐标下，用两条清晰 chirp 的平均去载波特征向最差两条补充，修正不超过各自 RMS 的 7.5%。相对同一物理轨迹无噪输出，受修正 chirp 的非载波误差总和下降 18.02%。将参照替换为同一源 RX 的其他包后仍下降 16.36%，真实噪声轨迹修正下降 18.53%。这些反事实只衡量波形。部分下降可由去噪和回归到公共 chirp 解释，需要冻结识别器的结果判断设备细节是否保住。本段不读取 F、TX 真值或目标，正在运行的训练未使用此信息。
